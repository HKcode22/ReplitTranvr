## New implementable evidence workflow

- Added pure `scripts/v39_p2g24_saved_original_item_evidence_v39.ts` — no database, network, blob SDK, provider subscriptions or log writes. For each already saved original, require exact LOGGED content SHA-256 and byte-length, production original-JSON duplicate/escaped-field structural parser, strict UTF-8 and exact canonical saved JSON representation. Invalid or missing source fails closed; no partial proof that all 30 were inspected.
- Aggregate only, no raw flight data or object keys: `originalStorageReferencesVerified`, `uniqueCanonicalSourceObjects`, `duplicateCanonicalSourceObjectReferences`, `notificationItemsInSavedObjects`, `explicitCostCreditClaimTotal`, per-original missing/invalid cost claim counts, and source content item-vs-cost disagreement counts. **One webhook can represent five flight items/credits**; do not conflate a notification count with its billable items.
- Add pure `summarizeCurrentRuntimeLinksForPreservedSourcesV39`: join the preserved LOGGED object-ref UUID and body SHA to **whatever currently exists** in UNLOGGED `clean.prepaid_probe_delivery_runtime`, counting exact reference/SHA matches, LOGGED originals without a *current* UNLOGGED delivery, current UNLOGGED deliveries without matching LOGGED reference, SHA conflicts, invalid item/cost values and source-item disagreements. Crucial explicit output: **`afterCrashHistoricalRuntimeCannotBeInferred:true`** and **`missingCurrentUnloggedRowsDoNotProveMissingUpstreamSends:true`**. No synthetic retroactive recovery or invented time of provider send.
- Extended existing P02 actual zero-mutation CLI `scripts/v39_p2g24_readonly_blob_integrity_audit.ts` with a **new strictly optional mode** requiring **BOTH** `--verify-objects --verify-item-credit-evidence`. Original `--verify-objects` behavior remains unchanged. It checks the hard-coded exact failed probe/session/budget, read-only transaction, count of exactly 30 unretracted, saved LOGGED refs, downloads all originals with SHA/byte verification, then (only after all 30 pass) runs aggregate analysis and SELECTs the current UNLOGGED delivery reference/cost rows. No mutation, provider call, new bucket, cloud host or original-content copy, and no object/provider/flight identifiers are included in outputs.
- Paid source `persistPrepaidProbeWebhookV39` remains unchanged by this P14 audit. No promise that script can actually run after the original object retention expires (earliest P02 metadata expiry Oct16); preservation/extension would require separate authorization and privacy/retention review. The existing original P2G24 probe remains **failed**, `duration_censored=true`, `reconciliation_status=UNRESOLVED`.

## What it cannot infer, even if 30/30 pass

Saved notification body's `deliveryAttempt.costCredits` is a **stored SOURCE CLAIM**, not authenticated external billed item credits; source metadata may lack explicit cost. An original provider webhook never received by Replit has **no stored object** to examine. A missing current UNLOGGED delivery after crash does not prove any specific original message was lost before SQL; the ref and current DB may belong to different lifecycle epochs. Duplicate identical canonical stored objects are not automatically separate original billed sends, nor proof of overcharge. These checks cannot prove the real historical 260-versus-259 mismatch arose before the edge, during SQL, or through a cost/item mismatch. The source body stored by the current paid receiver is canonicalized parsed JSON, **not literal original HTTP wire**, so provider-specific original-wire byte claims remain unknown.

The resulting audit output explicitly carries `independentUpstreamSenderAttemptCount:null`, `independentUpstreamBilledFlightItemCredits:null`, `upstreamProviderAttemptsNotSeen:null`, `providerBillingVersusInternalExactMatch:null`, `actualProvider260Versus259CauseResolved:false`, `canDeclareF8Complete:false`, `canAuthorizePaidLaunch:false`, zero mutations/provider calls.
