## Key finding: restoring a flight row is NOT the same as recovering its scientific origin

1. [Actual V3.9 local PostgreSQL replay CI #38091136947](https://github.com/HKcode22/ReplitTranvr/actions/runs/38091136947) proved that re-ingesting one original provider-like wire body through the existing published-style **HTTP callback** after a disposable UNLOGGED reset **can recreate an identical physical-v2 flight instance and delivery hash**, but it writes a **new processing UTC** rather than the independently frozen first-edge UTC. It also writes an additional LOGGED `provider_content_blob_ref` for the same logical source ID. This case prints `P13_REINGESTED_ACTUAL_V39_ORIGINAL_UTC_PRESERVED=false`, `P13_REINGESTED_ACTUAL_V39_LOGGED_REF_DUPLICATED=true`, and `P13_REINGESTED_ACTUAL_V39_SCIENCE_PASS=false`. HTTP replay alone is therefore NOT an approved science recovery.
2. [Actual V3.9 lower-level persistence CI #38091433432](https://github.com/HKcode22/ReplitTranvr/actions/runs/38091433432) proved that a **test-only**, explicit `receivedAtUtc` original fixture timestamp passed to `persistPrepaidProbeWebhookV39` can restore original item UTC along with the same raw item SHA, delivery ID and physical-v2 ID after a disposable UNLOGGED reset. However it **still duplicates the retained LOGGED source blob reference**, so this is a possible recovery architecture ingredient, **NOT an approved replay path**. The source edge timestamp in this test is declared fixture data, not provider-authenticated.
3. New read-only source audit `experiments/phase2g_rehearsal/disposable_replay_blob_ambiguity_v39.ts` classifies per **exact session+logical delivery ID** a pristine 1-LOGGED/1-UNLOGGED reference, an orphaned 1-LOGGED/0-UNLOGGED state after reset, and duplicate 2-LOGGED/1-UNLOGGED references after manual re-ingestion. It checks logged-ref hash conflicts, unexpected logical delivery IDs, missing source references, orphaned sources and recovered delivery SHA mismatches. The auditor uses **only localhost disposable PostgreSQL** and returns `scientificPassAuthorized=false`, `paidRunAuthorized=false`, `replayCanBeTrusted=false` regardless of counts. Its final SQL integration is pending/under CI verification at document creation.
