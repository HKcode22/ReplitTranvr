## 7. Required launch safety path

The live run must use all of the following controls. Do not bypass them with a direct owner command.

### A. Exact read-only paid preflight

`scripts/v39_phase2g_stage1_paid_preflight_v39.ts`

It re-binds the exact Git head, AUTH bytes/SHA/ledger approval, Gate-2 runtime, predecessor chain, budget day, provider balance, zero active billable subscriptions, zero active probes/incidents, workspace callback, protected callback source compatibility, frozen time class, and remaining AUTH duration.

It writes an immutable receipt. Only `PASS_READY_FOR_PAID_STAGE1` with zero blockers can feed the launcher. The receipt expires for launch after 10 minutes.

### B. Hash-bound persistent launcher

`scripts/v39_phase2g_stage1_launch_logged_v39.sh`

It refuses a stale/mismatched preflight receipt, production callback, unexpected Git head, or mismatched AUTH/runtime/preprobe hashes. It starts a detached supervisor and creates timestamped artifacts under `artifacts/`:

- `.log`
- `.status.json`
- `.heartbeat.json`
- `.pid`

Never launch a second paid Stage-1 process merely because a browser/terminal disconnected. Inspect these artifacts, database state, and provider state first.

### C. Supervisor and callback watchdog

`scripts/v39_phase2g_stage1_logged_supervisor_v39.ts`

The supervisor runs the normal paid front-door AUTH guard, re-verifies the exact AUTH, then starts the actual Stage-1 owner as its direct child. It writes heartbeats every 30 seconds and checks the public workspace callback every 15 seconds. Three consecutive callback failures trigger fail-closed termination of the owner followed by exact recovery.

### D. Abnormal-exit recovery

`scripts/v39_phase2g_stage1_recover_after_exit_v39.ts`

Recovery is scoped to exactly one `probing` Stage-1 row and its exact runtime session. It deletes only a provider subscription that is proven to belong to that session. It also handles the narrow create→bind crash interval only when the active subscription exactly matches the deterministic callback URL, `FlightByAirportIcao`, and the exact probe ICAO. Ambiguous or unmatched billable subscriptions cause refusal + incident, never bulk deletion.

An abnormal/interrupted run is marked `failed` / `UNRESOLVED` and an incident is opened. Recovery never fabricates PASS.

### E. Pre-sleep unattended health gate

`scripts/v39_phase2g_stage1_sleep_check_v39.ts`

Before the user leaves the live run unattended, this read-only check must report `RUNNING_HEALTHY_UNATTENDED_WINDOW`. It verifies the detached supervisor, heartbeat freshness, persistent log, exactly one probing Stage-1 row, active runtime session, exact owned credit-based provider subscription, zero foreign billable subscriptions, zero incidents, and reachable callback.

If it reports `BLOCKED_DO_NOT_RELAUNCH`, stay awake and inspect; do not start a second probe.

## 8. Whole-workspace failure boundary — unresolved before paid launch

The detached supervisor protects against terminal/browser disconnects and child-process failures **while the Replit workspace remains alive**. It is not an independent external cleanup agent.

A complete Replit development-workspace/container termination can simultaneously remove the callback, owner, supervisor, recovery process, and UNLOGGED runtime rows. Therefore the paid run must **not** be represented as safe against total workspace termination merely because `nohup` is used.

Before the first paid Stage-1 launch, either:

1. keep the Mac plugged in, awake, lid open, network connected, and Replit workspace actively available for the full live window, and explicitly accept that residual host-failure boundary; or
2. preferably add an independent external watchdog with its own secure provider credential and exact ownership rules before launching.

Do not silently weaken the 500-credit safety claim. If an external watchdog is added, it must never bulk-delete provider subscriptions and must be independently tested before use.
