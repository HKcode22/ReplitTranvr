## 7. Root cause / design gap exposed by attempt #1

The three prepaid runtime tables are intentionally `UNLOGGED`. PostgreSQL may reset UNLOGGED table contents during crash recovery/restart. That privacy/storage boundary remains intentional, but the first implementation left the random runtime-session UUID only in the UNLOGGED session table until the live window returned.

Therefore a runtime reset could erase the only durable ownership bridge needed for automatic exact provider cleanup. The persistent `adb_anchor_probe.runtime_session_id` field already existed for a safe random UUID binding, but the first execution path populated it too late.

The exact external reason that the supervisor/owner processes vanished has not been proven. The old launcher used a plain background/nohup process arrangement, so the repaired launcher also isolates the supervisor into a separate OS session/process group. This is hardening, not a claim that terminal job-group termination was definitively the original cause.

## 8. Repair contract before any new paid attempt

The current repair must satisfy all of the following before a new authorization is considered:

### A. Durable random session binding before provider creation

`server/lib/disruption/probeExecutionPrepaid_v39.ts`

The existing `runPrepaidLiveWindowV39(... onSessionArmed ...)` hook is now used to write the random runtime-session UUID into the logged `adb_anchor_probe.runtime_session_id` row immediately after the UNLOGGED session is armed and **before** `createSubscription(...)` is allowed to run.

Only the random UUID is durably retained. Provider subscription IDs, balances, normalized provider content, and raw payloads are not moved into logged PostgreSQL evidence.

### B. Exact recovery after UNLOGGED runtime reset

`scripts/v39_phase2g_stage1_recover_after_exit_v39.ts`

If the UNLOGGED session still exists, recovery retains the existing exact-session behavior.

If the UNLOGGED session has disappeared but the logged probe contains the durable random runtime-session UUID, recovery may reconstruct ownership only when there is exactly one active subscription matching all of:

- `CreditBased` billing;
- `FlightByAirportIcao` subject;
- exact probe ICAO;
- `WebHook` subscriber;
- exact deterministic `/prepaid/<durable-session-uuid>` callback URL.

Zero exact matches with other active billable subscriptions causes refusal + incident. Multiple exact matches causes refusal + incident. Recovery never bulk-deletes subscriptions and never converts an abnormal run to PASS.

### C. Detached supervisor process group

`scripts/v39_phase2g_spawn_detached_supervisor_v39.ts`

`scripts/v39_phase2g_stage1_launch_logged_v39.sh`

The launcher now uses a dedicated Node spawner with `detached: true` and `child.unref()` rather than relying on a plain terminal background/nohup job. The launcher still performs the exact AUTH/runtime/preflight/head/callback guards and verifies the detached supervisor PID remains alive before returning success.

This protects against interactive terminal job-group lifecycle events. It does **not** create an independent external watchdog and does not survive destruction of the entire Replit workspace/container.

### D. Offline regression contract

Before any fresh Stage-1 attempt, CI and the workspace focused tests must prove:

`scripts/v39_phase2g_stage1_logged_supervisor_v39.ts`

### D. Abnormal-exit recovery

`scripts/v39_phase2g_stage1_recover_after_exit_v39.ts`

## 11. Whole-workspace failure boundary

The detached supervisor protects against terminal/browser disconnects and many child-process failures **while the Replit workspace remains alive**. It is not an independent external cleanup agent.

A complete Replit development-workspace/container termination can simultaneously remove the callback, owner, supervisor, recovery process, and UNLOGGED runtime rows. The durable random session binding now permits exact ownership reconstruction after the workspace/database returns, but it cannot itself delete a provider subscription while the entire workspace is unavailable.

Until an independently hosted watchdog exists, a paid run must keep the Mac plugged in, awake, lid open, network connected, and the Replit workspace active for the full live window. Do not represent this as protection against total host loss.
