## Phase 1 → Phase 2 technical explainer (2026-09-11)

A plain-language record of what we built, ran, and proved from Phase 1 (Gate 0)
through Phase 2B (Gate 1), plus the current Phase 2C state. Written for the
project owner, no prior context assumed.

### 1. The big picture in one paragraph

We are building a system that will collect flight-delay data from a provider
called AeroDataBox and turn it into a research dataset. Before collecting a
single paid datapoint, the project plan forces us through locked checkpoints
called **gates**. Each gate proves exactly one thing, writes down fingerprinted
proof, and then stops. **Phase 1 / Gate 0** proved "we know our account and
budget." **Phase 2 prerequisite P** proved "we have the legal and security
right to store each kind of data." **Phase 2B / Gate 1** proved "we know which
4,344 airports the provider covers." Next is **Phase 2C**: freezing the rules
that sort airports into groups.

### 2. Vocabulary decoder

| Term you saw | What it actually is |
|---|---|
| **Catalog** | Our own hand-kept list of 276 airports we care about (`adbAirportCatalog_v3.ts`). Think of it as our address book. |
| **Universe (4,344)** | Every airport AeroDataBox says it covers, across three data feeds (schedules: 3,325; live updates: 1,445; ADS-B: 1,750). Think of it as the phone book. Measured live at Gate 1, free of charge. |
| **Catalog in universe (266)** | The overlap: 266 of our 276 address-book airports appear in the provider's phone book. 10 do not (yet — they may be code mismatches or real coverage gaps, to be triaged, never silently dropped). |
| **Universe not in catalog (4,078)** | Phone-book entries we don't track: 4,344 − 266. Mostly small airfields. They stay visible in the data; they just aren't in our study groups. |
| **Hash (SHA-256)** | A 64-character fingerprint computed from a file's exact bytes. Change one comma and the fingerprint changes completely. We use hashes so nobody — including us, later — can quietly alter frozen evidence. Example: the Gate-1 artifact's fingerprint is `b66c82c6…2859`. |
| **AUTH record** | A small JSON permission slip: who authorized what, for which gate, with what spending limits, valid until when. Example: `AUTH-20260911-G1A` allowed only free coverage reads for Gate 1, zero spending. |
| **AUTH_ARTIFACT_SHA256** | The fingerprint of an approved permission slip, copied into the evidence ledger. The code refuses any permission slip whose fingerprint isn't in the ledger — this is what stopped your first Gate-1 attempt with `REFUSED`, and that refusal was the system working correctly. |
| **Ledger entry** | A dated section in `V3.9_RUN_REPORTS_AND_EVIDENCE.md` recording what happened: commands, results, hashes, verdict. Newest goes on top; old entries are never edited (a wrong old entry gets superseded by a newer one, preserving history). |
| **Feed (schedule / live / ADS-B)** | Three separate airport lists the provider publishes: airports with schedule data, with live updates, with ADS-B tracking. An airport needs schedule feed for pre-departure predictions and live-or-ADS-B for airborne ones. |
| **Tier (HUB / MID / REGIONAL)** | Size groups for airports. Still **unfrozen** — assigning them needs a traffic data source we don't have yet (see §5). |
| **Macro-region (NA/EU/AP/MEA/SA/OC)** | Six world regions. The frozen country→region rulebook is now code (`regionMapping_v39.ts`, fingerprint `5013634da96e…`), including the tricky cases: Turkey→Europe, Greenland→North America, Russia split at 60°E longitude. |
| **UNCLASSIFIED / UNMAPPED** | Honest labels, not errors. An airport with no traffic data is UNCLASSIFIED (can't join a size group yet); one with no resolvable country is UNMAPPED (can't join a region yet). The plan forbids guessing either. |
| **Retention matrix** | A 16-row table stating, per data kind, how long we may keep it and under what legal basis (raw provider data: 7 days; FIDS cache: 24 h; computed features: 365 days; internal metadata: permanent). Verified at prerequisite P. |
| **Verifier (`v39:security:verify`)** | A script that checks five things live: least-privilege database role, webhook security, retention surfaces, retention matrix evidence, incident-stop wiring. All five currently PASS. |
| **Tests (vitest)** | Automated checks that run without the provider: e.g. "missing AUTH → zero provider calls", "unknown country → UNMAPPED". Gate-1 work added 6; they pass alongside the whole offline suite. |
| **Replit commands you ran** | `git pull` (download latest code), `npm run v39:gate1:coverage -- …` (the authorized coverage run), `node -e …sha256…` (fingerprinting a file), `git add/commit/push` (recording work in shared history). |
