## 2. Prerequisite P — architecture now implemented correctly

### 2.1 Why the old PITR conclusion no longer describes the Phase-2 paid path

Owner evidence remains:

- Replit production PostgreSQL PITR: **On, last 7 days / 168 hours**.
- AeroDataBox Ultra account-plan retention evidence supplied by the owner:
  - ordinary raw API/webhook provider content: hard-delete maximum **168h**;
  - live FIDS cache: hard-delete maximum **24h**;
  - genuine Derived Works: potentially longer only when the retained output is truly transformed/non-reconstructable;
  - project-owned metadata with no provider content: not subject to the provider-content cache rule.

The earlier design stored paid/prepaid provider plaintext in logged PostgreSQL, so 168h PITR could extend effective recoverability beyond the provider maximum. The Phase-2 architecture no longer does that.

**Current isolated prepaid path:**

```text
provider webhook/raw bytes
    ↓
dedicated Replit App Storage object
    ↓ hash/ref only
PostgreSQL provider_content_blob_ref

transient prepaid subscription/session/item state
    ↓
PostgreSQL UNLOGGED prepaid tables

long-lived evidence
    ↓
project-owned aggregate/hash/audit fields only
```

Raw paid/prepaid bytes therefore do not enter logged PostgreSQL/PITR. Replit App Storage deletion is treated as an independently deletable object boundary and the P verifier performs a synthetic write/read/delete/absence test before PASS. Expired session cleanup deletes objects first, verifies absence, then clears transient UNLOGGED runtime state. Any destructive deletion failure opens persistent `adb_incident_stop(cause='deletion')`.
