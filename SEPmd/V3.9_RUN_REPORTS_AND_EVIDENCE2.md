### 2.2 AeroDataBox RapidAPI Ultra retention evidence supplied by the project owner

| Content class | Project/account rule being enforced |
| --- | --- |
| Raw API payload + webhook delivery | **Hard delete after 7 days max** |
| Live FIDS query cache | **Hard delete after 24 hours max** |
| Genuine Derived Works / analytics | **Up to 365 days**, but only for outputs that actually qualify as transformed/non-reconstructable Derived Works |

### 2.3 Public-provider cross-check

The public AeroDataBox Terms support the general distinction used by the implementation:

- ordinary API **Contents** include copies/extracts/reformatted source content;
- Article 5.5 governs ordinary caching/storage;
- genuine **Derived Works** require non-trivial processing and non-reconstructability of individual source values;
- Article 5.6 treats genuine Derived Works separately.

The public September material discussing **24-hour FIDS** concerns the size/range of a FIDS request for certain plans. It is **not** being used as proof of this project's 24-hour retention limit. The 24-hour retention rule remains recorded as project/account-plan evidence supplied by the owner.

Public references used during the audit:

- `https://aerodatabox.com/terms/`
- `https://aerodatabox.com/2026-09-terms-update`
- `https://aerodatabox.com/pricing/`

### 2.4 PITR compatibility conclusion

A primary-database delete does not prove contractual expiry if an older recovery point can still reconstruct the plaintext.

| Class | Primary maximum | Plaintext PITR window | Conservative recoverable age if deleted only at max TTL | Current verdict |
| --- | ---: | ---: | ---: | --- |
| Raw provider content | 168 h | 168 h | **336 h** | **BLOCKED** vs 168 h hard maximum |
| Live FIDS cache | 24 h | 168 h | **192 h** | **BLOCKED** vs 24 h hard maximum |

Therefore migration 0048 and primary-row nullification alone cannot make P PASS. A compliant design must prove that expired provider plaintext is no longer recoverable from PITR, or the recovery topology must change in a way that makes the effective recoverable lifetime compatible with the applicable hard limit.

### 3.2 Remaining P blockers

P intentionally remains BLOCKED for reasons that are now machine-visible rather than hidden:

1. **Replit 7-day plaintext PITR is incompatible with the current raw/FIDS hard limits** under the conservative effective-recoverability calculation.
2. **Flattened/copied provider values exist outside raw JSON.** Examples include webhook-derived status/milestone/location/identity fields, FIDS population fields, and raw airborne observations. Every provider-bearing scope needs either expiry or a valid Derived-Work/non-provider classification.
3. **Mixed tables cannot be classified wholesale.** Tables such as event/trajectory/snapshot stores contain combinations of copied provider values, ETL metadata, and genuinely computed values.
4. **Unknown or deployed replica/object/log surfaces must remain fail-closed** until evidence proves whether they contain provider plaintext and how expiry is enforced.
5. A **Derived Work label is not enough**. The exact retained values must satisfy the transformation/non-reconstructability basis used for the 365-day class.

The content-inventory test is therefore designed to BLOCK until these scopes are resolved. That failure is a safety control, not a defect to suppress.

1. `v39:security:verify` passes all P checks;

### 4.2 Final traffic-reference contract

A new traffic-reference owner validates the future frozen reference instead of letting the frame builder improvise tiers. The final reference must carry the Plan-required provenance, including:

- one frozen 12-month period;
- source name/version and retrieval date;
- metric name/units/value per airport;
- deterministic HUB/MID/REGIONAL cut rule;
- exact missing-reference behavior;
- raw/reference SHA-256;
- sorted ICAO→tier hash;
- country/longitude/time-zone inputs needed by the final frame;
- degree/carrier/international variables needed by the balancing/anchor design.

No such permitted global reference has been supplied yet, so the live final frame correctly remains BLOCKED.

### 4.3 New binding final-frame owner

The production `v39:frame:build` command now points to `scripts/build_final_frame_v39.ts`, not the old provisional curated-tier builder.

The new owner:

- loads and verifies the P/Gate-1/traffic-reference prerequisites **before** touching coverage;
- re-reads only the documented-free coverage universe and requires it to hash-match the frozen Gate-1 evidence;
- uses the frozen traffic reference for tiers and balancing variables;
- uses the reviewed `regionMapping_v39.ts` country/longitude resolver;
- leaves missing-reference airports `UNCLASSIFIED` rather than guessing REGIONAL;
- records feed-specific PRE/POST eligibility;
- requires mapped, tier-verified, dual-eligible candidates for the core frame;
- versions/hashes every final frame.

Migration `0049_final_frame_reference_provenance.sql` adds the missing frame/registry provenance fields so the final DB state can prove which traffic reference, tier rule, region rule, period, and hashes created it.
