Build a full-stack web app called "Travnr" — a personal travel concierge platform. The app is the "home base" for a travel concierge service. Users create accounts, manage traveler profiles, request concierge calls, receive and approve travel itinerary proposals with line-item pricing, view a travel calendar, manage notifications, and handle billing/payments. The actual voice call experience is handled by a separate system — this app manages the user-facing web experience and provides webhook endpoints for the voice system to integrate with.

Use the Travnr logo I've attached as the app logo and favicon.

Authentication
Use custom email/password authentication (NOT Replit Auth or any third-party OAuth). Users register with first name, last name, email, and password. Passwords are hashed with bcrypt (12 rounds). Sessions are managed via express-session with a PostgreSQL-backed session store (connect-pg-simple). User IDs are UUIDs (gen_random_uuid).

Email verification is required. After registering, the user sees a "Check your email" screen with a mail icon, the email they registered with, instructions to click the link, and a "Resend verification email" button. A verification email is sent via SendGrid (from address: hello@travnr.com, sender name: "Travnr"). The email is branded HTML with a "Verify My Email" button linking to the verification endpoint. When the user clicks the link, they are redirected to /auth?verified=true, which shows a "Email verified" success screen with a green checkmark and a "Sign In" button. Unverified users get a 403 error when trying to log in, which redirects them to the check-email screen. If SendGrid is not configured, verification links are logged to the server console in development only (never in production).

The /auth page has login and register modes with a toggle between them. It includes a password visibility toggle (eye icon), inline error messages, and loading states on the submit button. The header on the auth page has the Travnr logo linking back to the landing page and a dark/light theme toggle.

Auth endpoints:

POST /api/auth/register — creates user, sends verification email, returns { ...user, needsVerification: true }
POST /api/auth/login — validates credentials, returns 403 if not verified, sets session
POST /api/auth/logout — destroys session
GET /api/auth/user — returns current user (strips password and verificationToken)
GET /api/auth/verify?token=... — verifies email, redirects to /auth?verified=true (does NOT set session)
POST /api/auth/resend-verification — generates new token, sends new email
Secrets needed: SENDGRID_API_KEY (secret), SESSION_SECRET (secret). Env var: SENDGRID_FROM_EMAIL = hello@travnr.com

Data Model (PostgreSQL with Drizzle ORM)
Users: id (varchar UUID PK, gen_random_uuid), email (unique), password, firstName, lastName, profileImageUrl, emailVerified (boolean, default false), verificationToken, createdAt, updatedAt

Sessions: sid (varchar PK), sess (jsonb), expire (timestamp, indexed)

TravelerProfile: id (serial PK), userId (FK to users), name, phone, homeAirport, passportCountry, seatPreference, hotelPreference, dietaryNotes, budgetRange, loyaltyPrograms, notes, updatedAt

CallRequest: id (serial PK), userId (FK), tripType (enum: flight/hotel/both), destination, dateFrom (text), dateTo (text), flexibility, timeWindow, status (enum: requested/scheduled/completed/cancelled, default requested), notes, createdAt

ItineraryProposal: id (serial PK), userId (FK), callRequestId (FK nullable), title, summary, totalEstimate (numeric 10,2), status (enum: draft/sent/approved/rejected, default sent), createdAt

ProposalItem: id (serial PK), proposalId (FK), type (enum: flight/hotel/other), description, priceEstimate (numeric 10,2)

Notification: id (serial PK), userId (FK), type (text), title, body, linkUrl, readAt (timestamp nullable), createdAt

Payment: id (serial PK), userId (FK), proposalId (FK), stripeCheckoutSessionId, stripePaymentIntentId, amount (numeric 10,2), currency (text, default "usd"), status (enum: unpaid/processing/paid/failed, default unpaid), createdAt

CallbackRequest: id (serial PK), phone, email, createdAt — stores public "Request a Call" form submissions (no auth required)

All enums are pgEnums. Define Drizzle relations between all tables. Create insert schemas with drizzle-zod, omitting auto-generated fields.

API Endpoints
All endpoints below /api/profile, /api/call-requests, /api/proposals, /api/notifications, /api/payments require authentication via isAuthenticated middleware that checks session userId.

GET/POST /api/profile — get or upsert traveler profile
GET/POST /api/call-requests — list or create call requests. Creating a call request also creates a notification.
GET /api/proposals — list user's proposals
GET /api/proposals/:id — get proposal with items and payments included (verify ownership)
POST /api/proposals/:id/approve — approve a "sent" proposal, creates notification
POST /api/proposals/:id/pay — pay an "approved" proposal, creates payment record (status: "paid", with demo stripe IDs like cs_demo_timestamp and pi_demo_timestamp), creates notification
GET /api/notifications — list notifications
POST /api/notifications/:id/read — mark single notification read
POST /api/notifications/read-all — mark all read
GET /api/payments — payment history
POST /api/callback-request — public (no auth), validates phone + email
POST /api/seed-demo — authenticated, seeds demo data for the current user
Webhook endpoints (no auth, for external voice system):

POST /api/webhooks/call-status — updates call request status, creates notification
POST /api/webhooks/proposal-created — creates proposal with items from external system, creates notification
POST /api/webhooks/stripe — updates payment status

Design & Visual Style
Color scheme: Soft light-blue primary (hue 205, saturation 72%, lightness ~52% light / ~58% dark). Clean whites, subtle neutral grays. The primary color is used for buttons, links, active states, and accent elements. Background is near-white (210 20% 99% light, 215 20% 7% dark). Cards are slightly elevated from background.

Fonts: DM Sans for body text (font-sans), Playfair Display for headings (font-serif), JetBrains Mono for monospace. Import from Google Fonts.

Dark mode: Fully supported with class-based toggling. A theme toggle button (sun/moon icon) appears in the header. All colors have light and dark variants.

Border radius: Small (0.5rem default). Consistent throughout.

Animations defined in CSS:

fade-in-up: translateY(20px) to 0, opacity 0 to 1, 0.7s
fade-in: opacity 0 to 1, 0.6s
blink-caret: blinking cursor effect for typing animation
waveform: height oscillation 4px to 16px for voice visualization
Animation delay utility classes: .animate-delay-100 through .animate-delay-800
