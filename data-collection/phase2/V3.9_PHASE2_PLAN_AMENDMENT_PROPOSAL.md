# V3.9 Phase-2 Plan Amendment Proposal — Open Observed-Network Reference

> **NON-BINDING PROPOSAL.** This file does not amend `V3.9_DataCollectPlan_f.8.md` by itself. It exists so the methodology choice is explicit, reviewable, and made before any paid probe/yield/outcome is observed.

## 1. Decision being proposed

Replace the unavailable proprietary scheduled-route balancing reference in Plan §§4.1/4.5 with a fixed, open, independently measured **observed commercial-movement/network reference** derived from the latest complete four consecutive MrAirspace quarterly extracts (ADSB.lol observations + callsign-route validation), while preserving all anti-leakage, missing-data, hashing, tiering, and pre-probe freeze rules.

This is a change in measurement construct, not a claim that ADS-B observations are published airline schedules. Reports must use `observed`, `resolved movement`, and `observed route` terminology for these fields.

## 2. Why a formal amendment is preferable to silently reinterpreting V3.9-f.8

V3.9-f.8 §4.5 currently says degree/carrier/international variables come from a permitted/licensed **scheduled-route reference** and defines them using scheduled departures. The validated MrAirspace source reconstructs routes from observed ADS-B tracks; its own documentation explicitly says the schedules are extracted from ADS-B position transmissions. Therefore the existing wording and the candidate are not equivalent.

The source is nevertheless scientifically useful as an exogenous operational-network proxy. ADS-B/OpenSky data are used in aviation research to derive airport operational milestones and observed traffic flows, while network-science studies use degree and weighted flight-flow measures to characterize airport connectivity and hub structure. Examples reviewed for this proposal:

- Schultz et al., *Journal of Air Transport Management* 99 (2022), 102164, DOI `10.1016/j.jairtraman.2021.102164` — airport operational milestones derived from ADS-B messages.
- Chao, *Journal of Advanced Transportation* (2026), DOI `10.1155/atr/1703947` — OpenSky historical flight-list observations used for airport arrival/departure operational analysis.
- Cheung, Wong & Zhang, *Transportation Research Part E* (2020), 101826, DOI `10.1016/j.tre.2019.101826` — degree/topological and volumetric indicators used to measure global airport connectivity/hub importance.
- MrAirspace `aircraft-flight-schedules` — global quarterly flight/route extracts derived from ADS-B observations; ODbL-1.0.
- ADSB.lol open-data documentation — historical ADS-B data made available under ODbL-1.0.

This evidence supports use as a **measured operational-network reference**. It does not justify labeling observed movements as scheduled departures or using the reference as the Phase-6 passenger-population denominator.

## 3. Exact proposed replacement for Plan §4.1 reference-period/source semantics

Keep every existing §4.1 rule except replace the Source/Reference-period rows with:

### Source — proposed binding text

> **MEASURE→FREEZE:** choose one actually accessible/licensed exogenous airport-activity reference before final-frame rebuild. The reference may be either (a) published scheduled-service data, or (b) an explicitly labeled observed commercial-movement/route reference derived from independent historical operations. The chosen semantics (`scheduled_commercial_service` or `observed_commercial_movements`) must be frozen and used consistently in §4.5 definitions. OAG/Cirium access is not assumed. If no permitted source satisfying the selected semantics and its frozen quality rules is available, `TRAFFIC_REFERENCE=BLOCKED`.

### Reference period — proposed binding text

> Freeze exactly one 12-month window and never roll it during Phase 6. For continuously/monthly available sources, the window must end ≤30 UTC calendar days before frame freeze. For a **quarterly published source explicitly frozen under the latest-complete-quarter rule**, use the latest complete four consecutive source quarters available at reference freeze; the reference end may be at most **92 UTC calendar days** before frame freeze. If a newer complete quarter has been publicly released before reference freeze, rebuild using the newest four consecutive complete quarters. The source-cadence rule and maximum age must be frozen before any paid probe/yield observation.

Rationale: the 92-day allowance is tied to a maximum-length calendar quarter, not to convenience or observed experimental outcomes.

## 4. Exact proposed replacement for Plan §4.5 balancing variables when `reference_semantics=observed_commercial_movements`

If a scheduled reference is chosen, retain the existing V3.9-f.8 definitions unchanged. If the frozen semantics are `observed_commercial_movements`, use the following definitions and never describe them as scheduled quantities.

| Variable | Proposed observed-reference definition |
|---|---|
| Traffic | `traffic_metric_value = resolved observed departures` during the fixed 365/366-day reference after the frozen commercial-airport/route-resolution filters. Finite/nonnegative only. |
| Network degree | Directed out-degree = distinct resolved destinations with **≥53 observed movements over the fixed 365-day reference**; in-degree analogously; undirected degree = distinct connected airports either direction satisfying that route threshold. `53/year` is a deterministic observed-frequency analogue of approximately one movement/week, not a scheduled-service claim. |
| Carrier diversity | Use only the upstream three-letter ICAO `Airline` field on resolved observed departures. Never substitute callsign prefix when `Airline` is missing/invalid. `effective_carriers = 1 / Σ p_i²` over valid operator-coded observed departures. Also report `carrier_count_5pct = count(p_i ≥ 0.05)`, Shannon diversity, and `carrier_coverage_share = valid_operator_coded_departures / observed_departures`. |
| International share | `intl_share = observed resolved departures whose origin country != destination country / observed resolved departures with known origin/destination country pair`. |
| Traffic score | Keep existing `min(1, traffic_metric_value / hub_cut_metric)`. |
| Geo score | Keep existing `0.5*degree_norm + 0.3*intl_share + 0.2*region_rarity`. |
| Carrier score | Keep existing `0.6*effective_carriers_norm + 0.4*intl_share`. |

### Observed-reference commercial filter — proposed binding text

> For the MrAirspace candidate, both resolved route endpoints must exist in the frozen OurAirports metadata snapshot with `scheduled_service=yes`. This is a filter on observed operational records; it does not turn them into schedule records. Ambiguous/missing origin or destination is excluded rather than guessed.

### Route resolution — proposed binding text

> Prefer exactly two distinct ICAOs from the upstream callsign-route validation field; otherwise require exactly one origin ICAO and one destination ICAO from the track assignment. Any other case is unresolved/excluded. Record the resolution-method counts in diagnostics.

## 6. Known limitations that must remain in the binding Plan/evidence if approved

1. 2026-05-05 through 2026-05-07 are missing or considerably incomplete in the upstream Q2 release; no imputation.
2. ADSB.lol receiver coverage is not globally uniform.
3. Route extraction/validation can contain ambiguity or duplicates; unresolved cases are excluded under the frozen rule.
4. Observed commercial-airport movements are not equivalent to passenger demand, seat capacity, published schedule frequency, or AeroDataBox Phase-6 passenger population.
5. Carrier metrics are conditional on valid upstream operator coding; `carrier_coverage_share` must remain visible.
6. The source is selected and frozen before paid probe/yield/outcome data, preventing outcome-adaptive source selection.
