## 2. New named first-cycle outcome and population, before collecting new data

**Proposed first-cycle primary endpoint**: `PROVIDER_SCHEDULE_REVISION_ABS_GE_15_MIN` (binary). At the **fixed T−6h cutoff C**, on a prospectively provider-observed **scheduled service** at one of four eligible selected airports, predict if the provider's latest scheduled departure value observed **by frozen W=T+2h** differs from the *latest as-of C* scheduled departure by an **absolute ≥15 minutes**. Both source versions must be authentic V0077-bound FIDS originals with durable `availableAtUtc`, query-side provenance, eligible departure direction and an explicit stable *service* identity. `T` is the **first provider-native `departure.scheduledTime.utc` observed in actual PRE source**, not gate-out or runway time. The first T must be available before C, otherwise the row is ineligible/UNKNOWN and preserved in the denominator. The fixed W rule must be feasible from verified provider coverage and rights before approval; it cannot shift per flight based on outcomes.

**Identity strata, never silently pooled**:
- `PROVIDER_NATIVE_OPERATING_LEG`: positive stable independent native operating identifier across comparable originals. This permits actual *identity* but still not actual runway time.
- `CONDITIONAL_QUERY_FILTERED_SERVICE`: immutable provider **scheduled-service record** key from pre-outcome operator flight number, requested departure airport, destination, service date and first T; with exact original custody and exactly one eligible matching entry per original, no positive marketing or alternate leg, and frozen provider query filters `withCargo=false;withPrivate=false` as supported. This is **NOT** row-confirmed operating identity, not proof of commercial service or actual flight. It is a separate, bias-qualified, provider query-filtered source population. Identity conflicts, duplicates, ambiguous codeshares or missing source evidence become `UNKNOWN_OPERATING_IDENTITY_CONFLICT`; no merging with native-leg stratum into a claimed physical denominator. Source-bound positive identity proofs must be independently audited: a caller-set hash/boolean cannot authenticate originals.

**Label**: compute signed provider schedule-revision minutes = `last_provider_schedule_by_W - last_provider_schedule_by_C`; positive means later provider schedule, negative earlier; binary event `abs(revision_minutes) >= 15`. This is **a revision of provider-reported schedule**, **NOT** a prediction of actual departure delay, arrival delay, cancellation or physical takeoff. Do NOT use `revisedTime` that represents a movement estimate as if it were a new version of `scheduledTime`. A legitimate postcutoff original affirmatively showing unchanged schedule produces a **measured zero** for this narrow revision endpoint; no post source, source expiry conflict, unresolved identity, same-clock contradictory versions, duplicate native-key evidence, or absent first T => `UNKNOWN/CENSORED`, **never zero or an actual on-time flight**. Record how many eligibility units lacked as-of or POST observations. At least one postcutoff FIDS original is necessary, not evidence from missing Alert deliveries.

**Horizon**: headline T−6h; secondary T−24h and T−90m when genuine on-time, with independent cutoff source and T24 witness; same W rule and separate label-evaluable denominator. No postcutoff source feature leaks into PRE.

**Outcome risk**: schedule revisions may be very rare, and Nov6's 36 zero-positive comparisons do NOT establish learnability or calibration. Report label prevalence, positive sample count, source/identity attrition and the difference between confirmed-native and conditional service populations. With no positives or no comparable two-class test support, discrimination is `NOT ESTIMABLE`, not a flattering AUC.

## 3. Correct first-cycle model and statistical metric — no MAE substitution

**Frozen primary model comparison (proposed):** Model 1 XGBoost tabular classifier versus Model −1 **training-only empirical revision-event prevalence** baseline; use predicted event probabilities, **Brier score** as headline (lower better). Freeze any smoothing, hyperparameter selection and calibration method before model fitting using TRAIN/VALIDATION only. Set practical decision as **pilot improvement in Brier** `delta_Brier = Brier_baseline - Brier_Model1` with 95% **calendar-day block-bootstrap pilot interval**, computed on the protected future test set once, reporting its width and effective observed blocks. Positive pilot result requires `delta_Brier>0` and interval lower bound `>0`; all others `INCONCLUSIVE_OR_NEGATIVE` as appropriately labeled, not proof of a deployed model. Brier event prevalence baseline is derived strictly from TRAIN, never future TEST. A separate deployment-certification study would need an independent, adequately powered calendar-block test.

Preserve original **chronological split *rule*** `run_day_index=1..20 TRAIN; 21..25 VALIDATION; 26..31 TEST` frozen before first collection. Only **after Phase6 collection and before any fitting/tuning** materialize immutable actual TEST row IDs. Same service and its three horizon versions must not cross partitions, including any repeated-retime and codeshare aliases; protect flight/service identity date/time groups as applicable. A train-only rate baseline and 0-positive strata must be reported rather than treating zero labels from absent sources as true negative.

Secondary: log-loss, 15-bin reliability/ECE when bin/support permits, AUROC only when both classes present and valid denominators, terminal provider-reported cancellation/diversion as a **separate** status target, signed schedule revision minutes exploratory. Optional actual-only wheels-off delay only on a separately validated source-positive subset, with a distinct endpoint, **NOT** by reusing the binary schedule revision target. The old `delta_MAE >= 2 min` is inapplicable and must not be reported as the new primary.

## 4. Executable scientific guard (not an approval switch)

New pure module `server/lib/disruption/phase5ProspectiveProviderScheduleRevisionPrimary_v39.ts` is a **source-data-independent function**, not a collector:
- Requires reviewed source envelope and first provider-native T/strict source clocks, invariant conditional vs native evidence, exactly one source service match per original, an as-of baseline source, and at least one **later** comparable POST source by fixed W.
- Records ambiguous, expired, missing as UNKNOWN; refuses conflicting identical-availability source versions. It computes signed and absolute revision from source schedule versions only; it reports `physicalDepartureDelayLabel=false`.
- For a conditional query-filtered service record, reports `confirmedCommercialFlightInConditionalTier=false` and does not magically certify a physical operating flight.
- `auditP5FirstCycleMetricPlan` refuses using physical-delay MAE for the binary event and exposes `phase5FreezePassed=false`, `phase6PaidGo=false` even when pure schema/metric validation passes.
- The existing independently reviewed Phase4 G5A outcome module is **not edited**, and Nov6 pilot observations are never retrospectively reclassified as certified provider-native operated IDs.
- This module **DOES NOT** check a live legal license, Cache-Control, backups/expiry compliance, provider data provenance or Phase6 GO. Those must be separately verified from real receipts, application/plan rights and independent reviewer records.
