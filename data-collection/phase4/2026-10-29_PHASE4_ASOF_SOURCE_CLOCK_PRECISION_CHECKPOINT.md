## Real defect and conservative repair

The existing `phase4Gate5ReadOnlySource_v39.ts` candidate source reader required `q.available_at <= p.available_at` using JavaScript Date values before producing even an offline as-of denominator. Earlier source receipts exhibited real submillisecond differences that PostgreSQL retains at microsecond precision; JavaScript Date coercion destroys that granularity. The separately merged #265 precision sensitivity supported counting such submillisecond discrepancies without rewriting source values, but the read-only Gate 5 candidate path did not explicitly preserve that exact-precision determination.

Now the read-only SQL selects the **database-computed** `GREATEST(p.available_at,q.available_at)` and an exact PostgreSQL precision-compatibility flag. A row is only admitted if `p.available_at>=q.available_at`, or a reversed clock is **strictly less than one millisecond**; a longer inversion remains rejected. The adapter separately requires the flag to be exactly true, ensures effective time is never before either parsed clock and never after read-as-of, then uses effective time for first-observation selection and all PRE cutoff inputs. This protects against miscounting source availability before the durable parent receipt. No historical timestamps or provider raw content are rewritten.

Negative tests: exact SQL predicate exists, submillisecond mismatch verdict passes without certifying science; an independently rejected SQL inversion cannot be accepted even if JavaScript timestamps round together; effective receipt after a cutoff is not backdated; invalid effective clock rejects. The injected test reader simulates SQL verdicts; real PostgreSQL correctness remains separately tested by existing integration CI. **This is an offline candidate proof repair**, not a live genuine first-selected-T validation, original signed provider receipt certificate or Gate 5 PASS.
