**What this fixes:** original f.8 §§5/16 + hash-locked implementation log §1.9 require population → horizon eligibility → expected/created PRE, plus independent webhook **captured inside, captured outside and unresolved**. A previous `scripts/v39_gate5_owner_v39.ts` owner remained intentionally BLOCKED because it assigned outside population without independent verified source. This file documents a useful *one-piece engineering implementation*, not a synthetic full Gate 5 PASS.

New reusable pure module `server/lib/disruption/phase4Gate5IndependentCapturePartition_v39.ts` takes **independently source-authenticated future inputs** (not present in Nov2 nonretained source-only series). It reports the following per horizon T−24h, T−6h, T−90m:

- Count separately (i) source primary physical-leg candidates, (ii) confirmed operating source members observed *before the flight-specific prediction cutoff*, (iii) truly persisted PRE candidates and missing PRE, (iv) marketing/unknown identities, and (v) known primary source-member but too-late/no-cutoff cases.
- Count webhook **distinct resolved physical legs inside the as-of eligible set**, **resolved physical legs known primary but cutoff-ineligible**, **resolved flight identities outside the sampled observed primary source frame**, plus **unique unresolved and conflicting notification IDs**; multiple retry attempts count separately as billable/physical attempts and NEVER as new flights. "Outside sampled frame" is not a claim to know the provider's entire global flight universe.
- Reject duplicate physical flight+horizon input rows (FIDS refreshes or marketing records must be upstream deduplicated), contradictory attempts, fake PRE where source arrived after cutoff or is not an operating leg, malformed time windows/digests, source/delivery from the future. Zero eligible denominators => NULL with reason, not false 0% missingness. Absence of webhook does not mean on-time flight or negative label.
- No provider calls, no database writes, no flight identifiers in output, no Phase5/6 authorization; input flags and SHA hashes remain *caller-supplied* and are not independent source/GH/DB authentication. **Cannot claim Gate 5 scientific PASS** from pure offline code.

Tests: `tests/phase4_gate5_independent_capture_partition_v39.test.ts`. These simulate inside/outside/codeshare/unknown, late source, duplicate webhook retransmissions, unresolved and conflicting notification statuses, NULL denominator, no historical backfill, zero provider/DB I/O.
