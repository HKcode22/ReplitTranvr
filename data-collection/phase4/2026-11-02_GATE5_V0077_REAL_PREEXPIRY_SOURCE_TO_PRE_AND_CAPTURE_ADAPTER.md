2. `server/lib/disruption/phase4Gate5BoundSourceCaptureReadonly_v39.ts`: OPTIONAL single-snapshot 9-original source, PRE and subscription-scoped callback **candidate** readback *only when all originals really remain lawfully retained*. Joins V0077 to V0076 physical attempt and source receipt; requires all 3×3 bound originals before provisional live-scoped funnel; uses existing `phase4Gate5IndependentCapturePartition_v39.ts` to preserve source operating denominator, actual PRE candidate, in population, known but cutoff ineligible, outside **observed** frame, unresolved, conflicting and repeat notification items. No subscription mapping = **capture unknown**, not zero. Missing source = **denominator unknown**; no after-expiry statistical promotion. Treating one physical HTTP delivery with multiple callback items as several physical attempts remains an unverified edge; report notification item attempt rates separately from verified HTTP attempt counts.
3. New tests `tests/phase4_gate5_horizon_preexpiry_readonly_v39.test.ts`, `tests/phase4_gate5_bound_source_capture_readonly_v39.test.ts` ensure binding, source/hash/clock, expiry, PRE-time, dedup, unknown, cutoff, missing receipts and no writes.

Both modules are **library readers**, not hooked to production credentials. Callers must establish one `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY` transaction, independently authenticate the review manifest bytes/sha, exact GitHub owner run and legal source rights, **never print returned source record identifiers**, and retain any proof only to permitted non-Contents TTL. ## Why read before expiry is mandatory

The frozen T−24h FIDS original can reach its technical source TTL well before T−90m and postflight. No 9/9-at-once postflight original-body audit can be assumed when only ~24h raw retention is permitted. Schedule each source/horizon independent readback early while 3 originals remain legally accessible, then combine *lawfully retained metadata evidence* with real future PRE/POST and webhook numerators. The alternative full-nine reader is only optional for a genuinely longer permitted short-lived source lifetime, not the primary pipeline.
