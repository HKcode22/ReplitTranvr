# Phase 4 Gate 5 — one truly free worldwide NOAA weather source integration

**Scope:** Supporting weather (important for bias/feature quality), not a substitute for original f.8 §5 flight population, T semantics or postflight outcomes. Plan §5, §16, hash-locked Implementation Log §1.9, narrow corrective Amendment B remain governing.

## Why NOAA is the first free integration

Official [NOAA AviationWeather.gov Data API](https://aviationweather.gov/data/api/) serves **worldwide** METAR observations and TAF forecasts without a paid aviation subscription. API currently allows 30 days historical access, requests limited to **100 per minute** and most endpoints max 400 rows; single **four-airport, one-GET** weather source sample is deliberately much smaller than either cap. A custom User-Agent is supplied per NOAA guidance. Real downstream PRE evidence must include both *weather report publication/source receipt* and *our own durable source availability time*; a forecast or METAR observed before cutoff but downloaded afterwards is NOT a valid historical PRE feature.

A new GH-only workflow `.github/workflows/phase4-gate5-free-noaa-weather-receipt.yml` runs **once when its source files change on main**; no cron, subscription, provider secrets or new paid request. It retrieves **four existing study-region airports** `WSSS, OMAA, SKBO, YSSY` in one bounded official METAR JSON request, saving both original raw public NOAA JSON and SHA-labeled extracted numeric weather receipt into a **3-day ephemeral GitHub artifact**. A separate second GitHub job **downloads the already uploaded artifact**, recomputes exact source SHA and normalized receipt, then calls the **existing** `phase4Gate5WeatherAsOfFeature_v39.ts` PRE weather selector with an actual post-artifact cutoff. If individual stations have no usable latest data, reports **missing** rather than fabricating weather; non-US stations may have uneven coverage. One successful retrieval is not a source-completeness or long-run reliability certification.

Current source implementation:
- `server/lib/disruption/phase4Gate5NoaaMetarReceipt_v39.ts`: strict official `icaoId`, Unix-second `obsTime`, independent optional provider `receiptTime` and `reportTime`, our HTTP completion, later durable artifact readback, finite unit-labeled numeric feature subset. Refuses future observations/reports, stale >48-hour rows, nonfinite values, unexpectedly large responses and unsupported stations; deduplicates multiple observations only within a station.
- `scripts/v39_phase4_gate5_free_noaa_metar_actions.ts`: one real NOAA GET, exact GitHub main job context, no AeroDataBox, no database, hash/metadata evidence only, no flight identities or provider Contents.
- `tests/phase4_gate5_free_noaa_metrar_receipt_v39.test.ts`: source/report/receipt/cutoff clock guards, local download versus independently stored artifact, late weather, station mismatch, missing/no data, duplicate station, malicious JSON and zero-provider regressions.

**Important:** Even after a green future GH NOAA workflow, historical Flight PRE is NOT automatically materialized. First run's downloader writes a local file *before* artifact upload, so the independent uploader/download job proves only that weather was available **by the later readback time**. No pre-cutoff values may be retrospectively applied to flight cutoff times. To support future true PRE, the Phase4 real source owner/feature pipeline must use its **own** already-durable weather receipts available before every flight's actual prediction cutoff; no after-the-fact backfill.
