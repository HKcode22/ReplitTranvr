## Why
The October 31 WSSS experiment lost its T−24h dated cron and T−6h schedule; the 3:07 AM event finally executed five hours 35 minutes late and correctly held before a paid GET. One 7:37 AM GitHub push-prearmed T−90m source succeeded (86 provisional rows, 2 API units), and three postflight read-only audits succeeded without certifying a physical-flight population, source-native T, actual wheels-off, or persisted PRE. The original **one request per earliest horizon** was an operational feasibility test, not the complete within-interval nonadaptive refresh grid required by Plan §5.2.

## New pure code / tests
- `server/lib/disruption/phase4Gate5FrozenGridDraft_v39.ts` implements **only** a deterministic full-window FIDS retrieval grid proposal for T−24h, T−6h and T−90m. Requires one explicitly frozen future airport/service interval and IANA timezone, assignment freeze timestamp, guard, refresh cadence, maximal staleness, GitHub prearm lead, project category REST budget, units/attempt and permitted attempt ceiling. Produces repeated same-interval query requests and counts; every request is marked requested-airport Departure with `withLeg/withCancelled/withCodeshared=true`, `withCargo/withPrivate=false`. Opposite-leg context does not prove departure population membership.
- Each grid begins at `service_window_start - H`, includes `service_window_end - H`, and inserts a final target if the fixed cadence does not land exactly on the end. Its **planned** physical dispatch time is `grid_cutoff - guard`. It rejects a freeze after first needed prearm deadline; the caller must **actually see a running authenticated GitHub runner** before relying on it. A GitHub cron schedule is best-effort. A single hosted job is limited to six hours and CANNOT be assumed to survive the 18-hour T−24h→T−6h separation; implement/review separate verified job owners or a legally bounded handoff-chain before activation. These are implementation constraints, not bypasses.
- A nonadaptive grid candidate is not a per-flight selected-T certification: native source first observed schedule and final physical flight identity must still be independently verified. Distinct system availability/readback time must be no later than the actual flight-specific cutoff; any late/missing result is `UNOBSERVED`. Query-boundary inclusivity/truncation also requires empirical validation.
- Forbid silently mapping a service interval across a changing airport UTC offset (DST fold/gap); require a deliberate verified split. A completed budget estimate reserves every physical allowed attempt, not just the first call. A held or expired quota is **not** a request authorization. These rules maintain the binding Plan §5.1 max-three-attempt REST contract but **do not change the separately bounded one-shot zero-retry prior trial**.
- `tests/phase4_gate5_frozen_grid_draft_v39.test.ts` uses synthetic future dates only; verifies example WSSS Nov 4 17:00–18:00Z 30-min cadence = 9 candidate queries, 27 worst-case physical attempts if each may be attempted 3 times, and 54 expected worst-case API units at 2 units/attempt. This is an illustration, **not a real sample, provider balance, cost reservation or approved Nov 4 schedule**. Tests cover budget excess, too-late freeze, cadence/staleness, DST fold, malformed times, provider parameters, and no self-authorization.
- No provider API key, HTTP request, DB write, new subscription, GitHub paid workflow dispatch, Replit command, Cloudflare or Phase 6 change.
