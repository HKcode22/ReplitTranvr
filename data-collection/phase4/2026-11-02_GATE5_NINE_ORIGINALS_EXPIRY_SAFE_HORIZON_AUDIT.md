## Material feasibility correction

The actual WSSS November 2 frozen service window was **17:00–18:00 UTC Nov 2**. Its original T−24h FIDS paid GETs ran roughly **16:30, 17:00, 17:30 UTC Nov 1**. An independent full postservice audit at or after 18:00 UTC Nov 2 would try to read those original Contents after approximately **25½, 25 and 24½ hours**, respectively. This exceeds the existing `live_fids_cache` **24-hour hard limit** in `retentionDeployment_v39.ts`, even without applying a shorter cache directive or purpose end. It would therefore reject a legally deleted T−24h source as *missing* despite correctly completed collection and cleanup.

**Never solve this by simply extending a DB TTL.** An account-specific right to do so remains unverified under #300. Nor should a later source replica or model output resurrect expired raw/normalized provider Contents. Generic 7-day public caching is NOT automatically lawful for every subscribed account or purpose; the repo's stricter 24h FIDS rule remains binding without a fresh reviewed deployment/change.

## Implemented source-to-cohort audit shape

`server/lib/disruption/phase4Gate5NineOriginalBoundCohort_v39.ts` uses the merged PR337 exact source request-frame reviewer and the existing `auditP4FreshCohortV39`. All calls use one **caller-owned PostgreSQL REPEATABLE READ READ ONLY transaction per audit**, no writes or provider calls.

1. **Normal lawful path:** `auditP4G5OneHorizonOriginalBeforeExpiryV39` accepts exactly three source UUIDs in a separately reviewed, canonical SHA-frozen grid, one horizon at a time. Validates the full V0076/V0077 query digest/reservation/original decoded body/source clock/expiry and airport-local FIDS flags while that horizon's raw data still exists. Returns *anonymous application-level statuses* and an exact per-horizon count; does not log or return source body/IDs. It does not certify source wire authenticity, retained metadata rights, GitHub job signer, native T or persisted PRE.
2. **Independent cross-horizon handoff:** `reconcileP4G5ThreeHorizonNoncontentReceiptsV39` compares one consistent 3-slot report for each of T−24h/T−6h/T−90m. Refuses a missing, duplicated or changed cohort/slot report. This is a syntactic check, **NOT authenticated GitHub log provenance**; another future reviewed independent GitHub job must fetch exact original Actions receipts and validate checksum, job+commit identity and lawful non-Contents metadata classification. Source SHA itself could be sensitive under a particular contract, so no automatic long-term hash-storage claim.
3. **Optional all-nine-same-snapshot diagnostic:** `auditP4G5NineOriginalBoundCohortV39` verifies all nine exact original source UUIDs, then checks generic PRE/webhook/outcome inventory **only** if both count of all airport-window FIDS receipts and retained originals equal exactly nine. Otherwise it returns `HOLD_MISSING_OR_EXPIRED_ORIGINAL_SOURCE_SLOTS` or `HOLD_UNBOUND_OR_EXTRA_AIRPORT_WINDOW_SOURCE_RECEIPTS`, with physical rates and denominator unknown, not zero. Under 24h FIDS retention, this optional postservice all-nine-raw path is *not expected to succeed* and must not become the primary acceptance test. It is relevant only if independently authorized retention duration actually permits it, not from a public default or a project-owner guess.

### What this fixes

Prior `phase4Gate5OriginalRequestFrameReadOnly_v39.ts` verified one source separately, while `phase4Gate5FreshCohortReadOnly_v39.ts` counted an entire airport/service window without proving that exactly the frozen nine originals covered it. A run could be green on unrelated FIDS rows. This new boundary refuses extra or missing source receipts and defines when source verification **must occur** to avoid lawful expiry making a healthy experiment look broken.

The test `tests/phase4_gate5_nine_original_bound_cohort_v39.test.ts` builds nine **synthetic** valid V0076/V0077/source-body rows, verifies that a postservice all-nine read legitimately finds only 6/9 at a 24h expiry (T24 3/3 expired), then runs three independent in-window horizon audits at early read clocks and reconciles all nine source status receipts without keeping original flight bytes. It also checks changed source request flags/hashes, duplicated IDs, extra airport-window query inventory and false scientific promotion. None of this proves a *real* flight-level cohort was collected.
