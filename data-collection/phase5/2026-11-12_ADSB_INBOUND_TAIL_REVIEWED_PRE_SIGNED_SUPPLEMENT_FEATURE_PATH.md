# November 12 — reviewed ADSB.lol inbound PRE features through the EXISTING Stage14 signed supplemental packet

**Scope: additive, offline optional input contract. No live ADSB API, no second FIDS reader or PRE writer, no database write, no new Phase6 GO.** Follows merged [#612](https://github.com/HKcode22/ReplitTranvr/pull/612), which established independently linked prior-aircraft ADSB PRE context and strict POST takeoff **proxy bracket** separately from the existing AIRBORNE handler.

## Why this additional change matters

The original Phase4 `assessP4Gate5DualSourceAdsbV39` purposely permits ADSB.lol only for AIRBORNE position context, not PRE or POST. Merged #612 adds legitimate *conditional* as-of physical incoming tail admission. However, Stage14 could not include that result in the existing signed optional PRE feature packet because the canonical Amendment E feature name/source whitelist did not include ADSB.lol. Simply renaming this incoming status as `prior_aircraft_turnaround_minutes` would be scientifically false, and writing an ad hoc second snapshot would violate our immutable original-source cutoff semantics.

This PR makes two new precisely named optional fields available in the original existing [Amendment E as-of selector](../../server/lib/disruption/phase5AmendmentEAsOfFeatureSelectionOffline_v39.ts) and [signed supplemental feature packet validator](../../server/lib/disruption/phase5AmendmentESignedSupplementalFeatures_v39.ts):

- `prior_aircraft_adsb_not_ground_reported`: boolean **true** only for ADSB.lol altitude/ground state of `NOT_GROUND_REPORTED`, **false** only for explicitly `GROUND_REPORTED`, and **NULL** for `UNKNOWN`. This is **not** an exact takeoff, actual gate arrival, current flight operating tail guarantee, or customer-facing runway truth.
- `prior_aircraft_adsb_position_age_seconds`: actual position-observation age **at the PRE issued-at time**, bounded to 0–900s. It must exactly reconcile to the reviewed original observation timestamp and true issued-at UTC, rather than trusting a caller-supplied ‘freshness’ number.

**Compatibility correction verified by existing regressions:** `P5_E_SUPPLEMENTAL_FIELDS` retains the original **12 fields in their original order**, preserving all frozen/default roster geometries and test expectations. The two extra ADSB names are accepted through a **separate opt-in admission list** only when explicitly selected in a new reviewed packet. Existing 12-field bundles remain byte-shape compatible. 

These are separate `source=ADSB_LOL` features—not `AERODATABOX_FIDS`, `REVIEWED_HISTORIC_CONTEXT`, `NOAA_TAF` or `NOAA_METAR`. The signed packet validator requires a real previously reviewed incoming ADB physical operating-leg/tail/ICAO24 link SHA, separately reviewed source capture original SHA, source-specific ODbL/retention review SHA, current flight departure airport binding, observation clock before system receipt, actual receipt **before issued prediction**, and a position no older than 15 minutes. No other field may pretend to originate from ADSB.lol.

New [`phase5AdsbInboundSignedSupplementCandidate_v39.ts`](../../server/lib/disruption/phase5AdsbInboundSignedSupplementCandidate_v39.ts) uses the merged #612 **pure** PRE review guard and maps eligible existing captured source metadata into the two field receipts. It does not itself sign an immutable packet: the field source original SHA, reviewed physical-flight link, independent source-use review and merged GH roster need an **external real signer and evidence review**. An unlinked/stale/late aircraft, unknown rights, tail swap or nonexistent previous leg emits **zero observations**, not a retroactive fabricated value.

The existing Stage14 [`phase5V0079SingleBoundFlightPreWriter_v39.ts`](../../server/lib/disruption/phase5V0079SingleBoundFlightPreWriter_v39.ts) already accepts optional `reviewedSupplementalFeatureBundle` with an independently reviewed original flight source, signed packet, and real DB-clock cutoff; **no change to that PRE writer, V0079–V0092 migration or production roles** is required by this contract. Its default remains to omit extra features until specifically released; initial production physical operating-leg linkage and ADSB.lol API/license admission are NOT proven by a SHA or test.

## The real unit test proves the correct narrow integration

[Focused signed-PRE regression](../../tests/phase5_adsblol_signed_inbound_pre_supplement_v39.test.ts) runs an authentic existing WSSS-style v2 ADSB point normalizer, accepted current + incoming separate signed-review candidate physical legs, original source and receipt clocks and a hypothetical externally reviewed SHA, then passes the resulting two candidate rows through the **actual existing Stage14 signed supplemental feature selector**. It expects correctly typed boolean/number builder inputs and source-record SHA, no raw ICAO24/callsign/registration/lat-lon in output and unchanged `independentSourceRightsCertifiedHere=false`. The failure cases include stale/backdated/late receipt; different tail; unknown original capture, ODbL/physical-leg review; falsified numeric age; wrong airport; wrong source; missing physical leg. No end-to-end LIVE original-to-ML proof is claimed.
