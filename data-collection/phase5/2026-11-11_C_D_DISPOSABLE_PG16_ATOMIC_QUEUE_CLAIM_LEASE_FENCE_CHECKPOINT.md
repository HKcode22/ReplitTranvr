## Exactly what is tested

- **100 synthetic flight×T−6h tasks**, with cutoff near the disposable PostgreSQL server clock and one approved synthetic packet SHA each. Eight separate asynchronous worker lanes each open a **short PostgreSQL transaction**, execute one atomic \`SELECT ... FOR UPDATE SKIP LOCKED\` claim and update task ownership/lease generation, **COMMIT immediately**, close connection. Each of 100 distinct IDs may be claimed once; count is measured in actual PG16 SQL. This is **NOT 100 real flights** and is NOT measured actual Stage14 PRE transaction latency.
- **Stable identity under schedule T revisions:** a UNIQUE database key on \`(flight_instance_id,horizon)\` rejects a duplicate record trying to use the same flight/horizon with a new native-T/cutoff. This test-specific design does **not** install such an index on live \`flight_snapshots\`; that requires inspecting actual unique keys and legitimate identity cases first.
- **Expired lease and fencing:** when a CLAIMED worker's lease expires **before the PRE transaction is started**, a reaper can return the task to READY and advance a generation. A new worker claims under a later generation. The old worker's attempt to change status has **zero affected rows**. This is a queue *metadata* fence; real Stage14 admission still must integrate lease/fence to prevent old sessions from entering the actual one-flight writer. Don't claim the experiment already has full stale-process protection.
- **Unknown COMMIT never blindly retried:** a row marked \`WRITE_STARTED_UNKNOWN\` remains excluded from the reclaim SQL even if its lease age has elapsed. An independent PostgreSQL \`REPEATABLE READ READ ONLY\` observer can read the quarantined task metadata, and a second owner obtains no task. In Phase6 it must separately reconcile against the actual immutable Stage14 \`flight_snapshots\` and finish its old transaction before any approved retry; **one missing-row SELECT alone is not proof of rollback**.
- **Real PG16, not current NeoN production:** validates localhost connection, db \`neondb\`, PostgreSQL>=16, explicit CI GITHUB_ACTIONS marker, no live provider secret, no paid process arm; CI results establish SQL control-plane semantics **only in disposable PG**, not performance or safe freeze.
