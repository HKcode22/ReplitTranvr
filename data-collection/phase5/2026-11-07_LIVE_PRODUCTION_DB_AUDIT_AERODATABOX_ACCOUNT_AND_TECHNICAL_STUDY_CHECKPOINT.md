## 4. Technical study notes — software + math

- **Git commit SHA** = content-addressed identifier of a whole repository commit; **Git blob SHA** = hash identifying the exact bytes of one file. Pinning both prevents a silently changed Shell command, but a hash is **integrity**, *not* an external license.
- **GitHub Actions / workflow YAML** = CI and scheduled jobs running from GitHub's servers; green CI indicates the tested code behaved under the stated inputs, not that live production observed flights. **Replit Shell** is an owner-operated developer terminal, not the trusted timed source scheduler. **Replit published deployment** may run an older built SHA than the local checkout or GitHub main.
- **TypeScript `interface`** defines shape and types of data objects, checked mainly at compile time; **runtime guards** check actual data coming from SQL/HTTP before action. Green `tsc` alone does not validate actual provider semantics.
- **PostgreSQL migration** = versioned schema change: `CREATE TABLE`, constraints, triggers and scoped `GRANT`/revokes; a staged SQL file in Git does nothing to production until a separate privileged, reviewed installer applies it. `to_regclass` returns table-name visibility/existence and does not establish row validity or grants.
- **`SERIALIZABLE`** = strong concurrent-transaction isolation aiming for equivalent serial execution; it can abort competing transactions and needs careful retry/duplicate protections. **`REPEATABLE READ READ ONLY`** = internally consistent snapshot used by audits that never write.
- **`clock_timestamp()`** = PostgreSQL's actual clock when queried, unlike `now()`/transaction `created_at`, which is the transaction-start timestamp. **Durability** means COMMIT became visible. The Stage14 post-COMMIT readback before the cutoff is direct on-time evidence for that one process; Stage15 native XID proof needs tracking ON, which the owner has now shown is OFF. The remaining design needs a **separately durable post-COMMIT witness ledger** before admitting T6/T90, or a separately reviewed alternative.
- **V0079 query/attempt/original** = three distinct records: what was authorized to request; whether a physical provider request may have been billed (reserve irreversibly); and which exact returned source response is bound to that attempt. **`PREPARED`** means permission/budget staged in the DB, *not* that a paid request happened or a flight PRE was collected.
- **FIDS** = flight information display data source request (REST API units); **Flight Alerts** = provider subscriptions/webhook notifications (separate Alert credit balance); **POST** = later outcome observation after the flight. Billing **SEND** versus received webhook can diverge; never treat missing webhook as a negative outcome.
- **Three PRE horizons:** `T−24h`, `T−6h`, `T−90m`, each keyed to a **provider-native frozen scheduled T**. A scheduled departure time is a predictor anchor, NOT actual runway wheels-off; after-the-fact observed source values would cause **data leakage**. Any late source/late PRE is unobserved/censored, not reconstructed with hindsight.
- **Population/denominator & codeshare:** avoid counting the same physical flight twice under marketing flight numbers; explicitly track unresolved operating-leg IDs and capture failures. **As-of join** means features only become eligible after their real persisted/available time and before their own prediction cutoff.
- **4 slots × 3 horizons × 31 days = 372 baseline source groups.** 5 hypothetical refreshes each gives 1,860 candidate GETs, `2×1,860 = 3,720` candidate REST units before retries and other categories. The signed f.8 crossover additionally requires **three 4h-vs-2×2h pairs and two 4h-vs-up-to-6h pairs**; Stage13 baseline four-hour proof is not complete 31-day experiment compliance.
- **Scientific FREEZE / GO** is an *independent evidence-based decision* confirming sampling, source-use rights, population, timing, source/POST outcomes, budget and safety. A passing unit test, paid approval or stored SHA is necessary but insufficient.
