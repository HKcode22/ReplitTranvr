- A policy commitment, start and end become immutable once the first window is claimed for that manifest. At least 15 minutes remain at admission, no retrospective claim or forced backfill. Maximum span 1440 elapsed hours, not an extension of the reviewed collection calendar.
- One atomic open root across the database, exact GitHub run ID unique, immutable manifest/window key, serialization with transaction advisory lock and existing authorization row. REPEATABLE READ callers refuse rather than seeing a stale snapshot. A missed unclaimed slot may be skipped, not replayed. A previously claimed slot is never reusable even if closed early. An expired **unresolved** root remains unresolved indefinitely, blocking new roots; timeout alone cannot prove no external request.

It does **not** independently validate GitHub receipts, worker settlement, source rights or actual flight labels. No automatic closure on exit, no replay or release.
- Table constraints, no public grants, owner-only executable functions; database owner remains trusted (not tamper-proof against owner). Disposable CI uses the exact original B0062 authorization DDL, not production.

## Avoid unnecessary new launch blockers

Existing canonical native schedules for early draw, daily prepare, SOURCE/POST, T24/later enrollment, T24/later PRE, and queue recovery already work independently of the rolling accelerator flag at the workflow-admission level. V0102 protects the rolling accelerator only, not all of Phase6. Preserve the native workers and their own release rules. A bounded live pilot should measure whether those existing scheduled routes can meet actual cutoff/coverage needs; if they can, baseline collection need not wait for the optional new controller root facility. If they cannot, use reviewed bounded parallel acceleration. Do not claim nominal cron reliability: actual prior repository observations showed hours-long creation gaps and the calendar/budget studies only modeled ideal cadence. Existing legally allowed, correctly timestamped partial observations remain usable; don't invent backfill or force every optional lane to succeed before preserving valid data. Reconcile unknown operations under original worker/queue/credit policy; do not require all already independently durable known downstream children to finish merely to keep a new controller window operational. Neither a GitHub aggregate nor a digest alone proves provider settlement or scientific validity.
