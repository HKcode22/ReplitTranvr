## Durable geometry and behavior

- Existing B0062 enabled singleton authorization must match exact authorization ID, manifest, calendar, config and reviewed code. This is an additional fence, not another paid GO or a substitute for signed budget, rights, STOP and worker admissions.
- A policy commitment, start and end become immutable once the first window is claimed for that manifest. Fixed 120-minute windows calculated using actual PG clock, anchored to reviewed policy start, not a new epoch chosen after crash. Final short window is truncated at policy end. At least 15 minutes remain at admission, no retrospective claim or forced backfill. Maximum span 1440 elapsed hours, not an extension of the reviewed collection calendar.
- One atomic open root across the database, exact GitHub run ID unique, immutable manifest/window key, serialization with transaction advisory lock and existing authorization row. REPEATABLE READ callers refuse rather than seeing a stale snapshot. A missed unclaimed slot may be skipped, not replayed. A previously claimed slot is never reusable even if closed early. An expired **unresolved** root remains unresolved indefinitely, blocking new roots; timeout alone cannot prove no external request.
- Owner-only close primitive binds exact root, final controller ID, independent review digest and verified terminal-receipt digest. Closure allowed after STOP for reconciliation. It does **not** independently validate GitHub receipts, worker settlement, source rights or actual flight labels. No automatic closure on exit, no replay or release.
- Table constraints, no public grants, owner-only executable functions; database owner remains trusted (not tamper-proof against owner). Disposable CI uses the exact original B0062 authorization DDL, not production.
