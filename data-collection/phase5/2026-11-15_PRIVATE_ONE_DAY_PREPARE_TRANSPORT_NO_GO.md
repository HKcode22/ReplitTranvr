# Phase6 — bounded private SOURCE preparation bridge (NO GO)

## Existing pipeline, not a new collector

The real original Stage7 saved-day read and Stage8 query proposal → Stage9 atomic V0079/V0082 prepare worker already exists and uses the commissioned Stage30 PREPARE LOGIN. Its older GitHub entrypoint requires a public checkout-local frozen preparation file. The protected per-day SOURCE registry is produced **after** the proposed queries are prepared and the original per-query packets are published. Reading that registry to get Stage7–9 input would create a circular dependency. Do not fabricate a registry to satisfy that prerequisite.

This patch replaces the one existing manual GitHub workflow's public file argument with one explicit day index and private review input. The small independently reviewed preparation-plan packet is supplied as canonical base64 in a dedicated step-scoped GitHub secret P5_SOURCE_PREPARE_PRIVATE_PACKET_B64 (max 48,000 encoded characters / 36,000 raw bytes). It is not a storage location for AeroDataBox response bodies, flight Contents or raw provider observations. Do not commission populated credentials or a packet before the applicable rights/review decision. The existing independently pinned expected SHA and reviewed day, calendar, config, frame, manifest, original exact saved draw, source proposal and category budget gates all still apply. The old path is only a logical identifier for backward-compatible admission; no file produced or looked up. Parsed object must match hashed bytes. Private bytes/object are nonenumerable; no payload in output, artifact, public repo or workflow dispatch inputs. Existing role, DB transaction and atomic ledgers reused. Provider keys blank and original scientific freeze, rights and Phase6 process arm gates unchanged. Live CLI rejects the file-based route; CI may use synthetic in-memory inputs only.

## Limits

This is a bounded one-day manual preparation bridge, **not** autonomous private 31-day release/publisher infrastructure. A base64 secret is transport, not encryption or a retention exemption. A future protected reviewer/publisher needs an independently authenticated dynamic day-input mechanism with lifecycle controls rather than requiring daily secret rotation or daily owner input. This patch does not install V0095/V0097, commission any secret, prepare a real day, reserve a query, dispatch a provider child, create synthetic flight labels or confer rights. It is not a request to run a paid workflow. Requires exact reviewed CI then separately approved future real plan and existing release gates. Overall FREEZE HOLD, Phase6 paid NO-GO.
