# Phase 5 Stage 2 — Single-physical-GET FIDS source/original bridge (review)

**Status:** API/code boundary candidate only. Offline tests; no production GH schedule, no source GET, no DB mutation and no paid permission granted by this artifact. Phase 5 final FREEZE and Phase 6 month-long GO remain HOLD.

## What was missing

After early preselector [PR #418](https://github.com/HKcode22/ReplitTranvr/pull/418) and Phase6 late-redraw repair [PR #417](https://github.com/HKcode22/ReplitTranvr/pull/417), the Phase6 runtime can consume an earlier committed four-airport draw, but **there is no linked FIDS GET/true PRE-producing scheduler**.

The general `fetchFidsPopulation()` helper historically defaults to `fetchFidsAirport()` and `persistFidsObservation()` if its caller omits explicit dependencies. `fetchFidsAirport()` itself defaults to the *ordinary app's* REST budget ledger and may attempt **three** provider GETs. Those defaults are not the locked G5A V0076 physical-before-request reservation, original exact V0077 binding, trusted DB clock, or provider-specific source rights. A new Stage2 caller must not accidentally fall back and spend or populate an unrelated DB.

## Code in this change

[Scoped FIDS bridge](../../server/lib/disruption/phase5ScopedFidsSourceBridge_v39.ts) adds two separate stages:

1. **Pre-provider admission**: expects one individually preregistered query for an already-drawn day/slot/horizon; verifies the exact day, slot, airport, SHA of the four saved early draws, provider request frame, approved source-rights fingerprint, max one physical attempt, independently approved per-attempt price (currently expected two API units), planned 120s etc worst-case source and persistence bounds, and a *trusted* DB clock safely before the earliest *planned* cutoff. This is only a necessary time bound; real per-flight provider T is a separate post-source determination.
2. **Explicit protected source and original**: calls `fetchFidsPopulation(params,{fetchAirport:...,persist:...})` with BOTH required handlers supplied, never the default application DB/budget callbacks. The supplied fetch adapter injects a reservation owner that requires **V0076-style durable scoped attempt** before the real provider function. Attempts to reserve a second physical GET are rejected **before** another transport call, even if a 429/503 auto-retry is suggested by the generic fetcher. The supplied persistence port must atomically bind the decoded body original SHA, all source rows, and exact reservation as V0077-style source/original custody, with actual DB-computed `sourceAvailableAtUtc` and conservative expiry. Unknown/ambiguous transport remains UNKNOWN; a late original is labeled **`BOUND_SOURCE_LATE_NOT_PRE`**, not backfilled. Even a timely original remains `SOURCE_ORIGINAL_BOUND_TIMELY_NOT_FLIGHT_PRE`: **never scientific PRE certification**.
3. A scoped read-only digest supports issue/audit checkpoints without raw Contents; no user data, provider responses or secrets are logged by this module.

[Offline tests](../../tests/phase5_scoped_fids_source_bridge_v39.test.ts) inject a fake HTTP transport and fake reservation/persistence transaction ports. They check approved versus denied source, actual early selection, request window timing, no silent generic DB usage, exactly one reserved attempt, **503 retry suppressed**, response-original binding mismatch, and late source not marked PRE. [No-provider CI](../../.github/workflows/phase5-fids-source-scoped-bridge-offline.yml) has blank provider keys/DB URLs and does not deploy.

## Critical unresolved dependencies

- **Only an interface/port, not a real V0076/V0077 integration:** The actual database-specific `reservePhysicalBeforeGet` and `commitOriginalAndPopulation` handlers are *not* implemented here; the original Gate5 owner used its separate cohort-specific SQL, which cannot be silently reused for a 31-day adaptive 4-airport experiment. The new exact release manifest/ACL/ledger SQL, distinct PRE owner, every physical-attempt idempotency and real disposable PostgreSQL16 tests remain required. A fake port can return an arbitrary ack; tests demonstrate *policy wiring*, **not** a real provider receipt or database commit.
- **Calendar consistency:** The earlier `phase5FidsFreezeGridAdmission_v39.ts` validates a **candidate static 31-day** acquisition grid; future adaptive REGIONAL airports cannot be assumed selected 31 days ahead. Each real day must preregister/freeze its own draws sufficiently early and publish **actual provider contract, REST unit price, local time ranges, cutoff and budget** before triggering a request. No retrospective changes or missing denominator erasure.
- **No FIDS timetable or actual PRE here:** A separate GitHub-only T−24h/T−6h/T−90m source scheduler must use this bridge and the exact original/bound normalizations. True PRE has to be written by V0076/V0077-derived approved SQL only if the original was durably available before the individual flight's cutoff. A source at the right *planned* time can still arrive too late for some or all individual flight cutoffs. Full analysis distinguishes physical operating legs, ambiguous codeshare, selected-T outcomes, ineligible, missing and unresolved.
- **Original Content and data rights:** Current provider contract, plan-specific retention/ML use and object expiry (#300), billed REST budget + Alert SEND ledger, deployed receiver SHA (#28) and POST/outcome matching remain independent signoffs. The mere shape `sourceAvailableAtUtc` from a callback is not independently verified evidence until it is produced/read back through the authenticated actual PostgreSQL transaction.
- **No provider GET or production table writes:** No workflow dispatch, scheduler, secrets or migration are included. Existing Phase4 G5A pilot stays closed with limitations; original strict scientific Gate5 HOLD does not disappear.

**Next release work:** a separate Stage3 database-specific, disposable-PG-tested V0076/V0077 31-day reservation and original writer backed by real immutable selected-day + FIDS query ledgers, then three-horizon GitHub timed admission and per-flight PRE reconciliation. Only after lawful retention, budget, receiver, scientifically bounded labels and independent Phase5 FREEZE may a separately approved Phase6 GO happen.
