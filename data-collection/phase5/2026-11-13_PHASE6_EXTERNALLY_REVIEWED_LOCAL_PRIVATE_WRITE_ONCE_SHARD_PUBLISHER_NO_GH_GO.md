## New guarded write-once private-local implementation

[`phase5PrivateWriteOnceLaterShardPublisher_v39.ts`](../../server/lib/disruption/phase5PrivateWriteOnceLaterShardPublisher_v39.ts) adds two deliberately small functions:

- `stageP5ExternallyReviewedLaterShardPrivatelyOnce(plan, wire, reviewerPublicKeyPem, externalPins, observedDbClockUtc, privateScope)` invokes the existing #630 full external Ed25519 signature verification over the exact #629 registry proposal, all per-flight packet hashes and protected rights/code/SOURCE/native time. This still requires a **genuine** independent production reviewer/previously pinned key fingerprint, real DB clock and legal source permissions; the function cannot attest those authorities by itself.
- It only writes to an **existing**, absolute, real-path, 0700, process-owned **private directory outside the entire public GitHub checkout**. It rejects symlinks/unsafe modes, GitHub checkout overlap and all existing target files. The independently signed SOURCE-day registry must already exist as private regular 0600 JSON and its exact byte SHA must match the external review before any new file is written.
- Every T−6h/T−90m reviewed packet is written to a random 0600 temp inode inside the same private directory, `fsync`ed, atomically **hard-linked** into its write-once final name without overwrite, directory `fsync`ed, reread and SHA verified. The proposed day-registry JSON is published **LAST**, after all packets' exact readbacks. This avoids losing native-time provenance through plain copy/overwrite/rename, and prevents two concurrent writers replacing one another.
- It rejects any selected flight whose actual T−6h or T−90m cutoff is missed or within 15 minutes of the **caller-provided** PG clock. It never retrospectively backfills. The caller is responsible for independently authenticating the clock as the actual restricted PG16 read-only DB timestamp; do **not** pass workstation time as if it were Neon.
- If a file collision or unknown commit/durability failure happens, **HOLD** with existing immutable files untouched. `inspectP5PrivateLaterShardReadback(plan, scope)` checks 0600 private files' actual bytes against reviewed SHAs, returning counts only and **`safeToBlindlyReplay:false`**. No automatic deletion, rollback or retransmission of uncertain PRE/data.
- Requires explicit `exactOwnerPrivateStorageApproved:true`, `adbAutoCollect:"0"`, `phase6ProcessArmed:"0"`. These approve **private local write-only staging** and explicitly do not grant a paid source, synthetic physical-flight identity, Stage14 write, V0091 task, GitHub worker dispatch, or scientific freeze.
- Returned receipt has only hashes, counts and truthful false flags: `privateRootOutsidePublicRepo:true`, `exportedPrivateFlightContentsInPublicRepo:false`, `immutableRemoteBackupProvenHere:false`, `githubConsumerCanReadPrivateRootHere:false`, `independentOrganizationalReviewerProvenHere:false`, `providerMLRightsProvenHere:false`, `phase6PaidGoGranted:false`. It deliberately omits real private root and per-flight identity from safe logs.

**Important durability boundary:** Atomic per-file hard links + fsync make each local file write-once, **not the entire multi-file shard transaction atomic**, not a guaranteed always-on storage service and not an immutable off-host backup. Registry-last is a commit marker but a mid-batch crash leaves some packet files and must HOLD for independent readback. The existing private root and an approved independent storage operator are still missing in production.
