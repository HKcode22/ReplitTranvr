## 3. Practical relaxations to consider, with accurate scope

**Now defensibly not hard blockers for every flight:** missing NOAA/ADS-B extra features; a single missed FIDS query or callback; a source that arrives late for one flight but in time for another's own cutoff; a conditional service key with valid versioned schedule observation but no physical departure; no immediately verified actual wheel-off for a secondary label; partial true PRE horizon coverage; a future window that can be prospectively rebooked before observation under a bounded policy.

**Still essential not to falsify evidence:** no assumed earlier source timestamp, no backfilled missed PRE, no unqualified provider-estimated `runwayTime` relabeled as gate-out or independently actual, no dropping a failed exposed day from sampling/TEST after seeing results, no repeated physical REST call billed outside its UTC ledger, no unpermitted provider Contents storage. These are small minimum requirements that make the result interpretable and protect account resources; they need not expand into a perfection loop.

**Prospective calendar flexibility:** [#536 bounded recovery reviewer](2026-11-10_CALENDAR_CONTINGENCY_SCIENTIFIC_FLEXIBILITY_PROPOSAL.md) has tests and can screen previously proposed backups for a truly unobserved future day. It does not edit a live calendar; an independent prospective affected-day revision is still needed. A missing optional source is ordinary recorded missingness, not a failure of the whole study.

## 4. Newly implemented target-neutral future POST *eligibility* logic

The historic [`v39_phase4_gate5_g5a_prospective_post_schedule_observation.ts`](../../scripts/v39_phase4_gate5_g5a_prospective_post_schedule_observation.ts) requires a particular **T24 source + PRE precursor** and hardcodes the Nov5 WSSS source range, three exact FIDS POST GETs, concrete GET request times and exact old billing ledger. This is not safe to reuse directly for 31 new dates and could cause avoidable loss if some true but later PRE was captured.

The new pure [`phase5FuturePostSourceEligibility_v39.mjs`](../../server/lib/disruption/phase5FuturePostSourceEligibility_v39.mjs) asks a narrower question: **does at least one same-identity truly source-bound, clock-valid PRE exist to make a future POST source observation scientifically usable?** It:
- Uses the **actual selected source-native T** per matched source/identity stratum, source availability and commit timestamps, and per-horizon true cutoff, preserving the three PRE result fields separately.
- Accepts 1/2/3 **valid** horizons descriptively; a missing or invalid one is recorded with a named gap rather than converted to "on time" or complete-case deletion. A true T24-only partial cohort is feasible with current T24 writer even if later PRE is missed.
- Supports a **proposed future extension** in which T6-only or T90-only can still be scientifically considered if those snapshots were really cutoff-safe. **IMPORTANT CURRENT LIMITATION:** the existing deployed signed T6/T90 Stage24 writer requires a durable T24 witness. T6-only/T90-only capture **cannot yet occur through that existing owner**. Any proposed relaxation must be independently implemented/reviewed without making an imaginary past witness.
- Uses **one generic planned future POST observation** (reviewed clock, source range, assessment window, UTC physical REST charge day) rather than hard-coded Nov5 WSSS. This is a **source observation eligibility** check only; it does not determine whether the label is gate-out, wheels-off, schedule change, cancellation or arrival, or whether it is actual versus estimated.
- Rejects forged/inconsistent original identity, duplicate horizon, wrong airport/partition/protocol, post time before scheduled source-native T, paid POST reservation replay, past post observation slot or unexpected protected TEST-outcome peeking. It **does not** assume the input's claimed original/cutoff timestamps are independently authenticated.
- Emits `PARTIAL_VALID_PRE_REVIEWABLE_FOR_FUTURE_POST_NO_DISPATCH`, `ALL_THREE_PRE_REVIEWABLE_FOR_FUTURE_POST_NO_DISPATCH`, `SKIP_POST_NO_VALID_SOURCE_BOUND_PRE_COUNT_MISSINGNESS`, `MISSED_POST_OBSERVATION_WINDOW_NO_RETROACTIVE_GET`, or `ALREADY_RESERVED_POST_NO_SECOND_PAID_GET`. All are **offline, without actual paid GET or native Operating-leg certification**.
- Requires **later external signed-release/source use/independent budget seven-category UTC admission, original POST body custody and real DB clock**. Test fixtures are synthetic; CI success does not prove that production POST is wired.

[Focused unit tests](../../tests/phase5_future_post_source_partial_pre_eligibility_v39.test.ts) include T24 missing and T6 valid, authentic three PREs, one late PRE + one valid, no PRE, duplicate/cross-flight, conditional identity, cutoff/expires, future-date physical charge day and TEST/cost/source safety. Dedicated no-secret GitHub CI refuses provider/DB contact. No new migration, role or manual Replit Shell.
