### Index fields and strong boundaries

- One externally reviewed index `SHA256`, separately supplied `expectedIndexSha256` and `exactExternallyReviewedIndexSha256` that must match **actual index bytes**. Each index binds one experiment `manifestSha256`, `calendarSha256`, one reviewed main `code SHA40`, signed release/rights digests, a monotonic revision and exact previous revision's hash.
- All entries require exact **day 1–31** and **shard 1–100000**, strictly allowlisted frozen JSON path, actual frozen JSON byte digest, independently claimed nonempty review evidence SHA, `publishedAtUtc`, `notBeforeUtc` and `hardLatestUtc`. Index entries cannot be published **after** the independently supplied database-clock instant or after the earliest dispatch time. Must be chronologically append-only; no silently rewritten/reordered earlier entries or skipped revisions.
- `SOURCE` records must contain real existing `v39.phase5.signed-per-day-source-batch-readonly.v1` JSON geometry (1–96 query packets); `LATER_PRE` records must contain the existing `v39.phase5.signed-later-pre-day-registry.v1` with correct per-day, per-shard and exact already-indexed SOURCE registry; `POST` records must contain `v39.phase5.github-future-post-reviewed-release.v1` with authentic future post input fields. All include exact byte SHA and day identity.
- A later PRE/POST entry cannot point to absent, different-day, later-published or different-hash SOURCE registry. Across **all** shards, refuse duplicate SOURCE query SHA, duplicate PRE flight×horizon or duplicate POST physical request SHA. Each lane must preserve existing distinct source legal/paid Stage14/V0081 and POST worker checks. The **index alone does not verify every underlying packet or source-use legal approval.**
- From the **supplied independently observed DB clock**, select **at most four currently due shards per lane** by earliest hard deadline, retaining full due/deferred/missed/not-yet-due counts. No backlog is hidden; expiration returns censored/missed *shards*, not fabricated missed flight observations.
- A cutoff is exclusive at `hardLatestUtc`. A source day can overlap another source day, a T6/T90 later PRE and a POST in UTC time, so no naive single-day-exclusivity rule. The selector emits no GitHub child, provider request, PRE write, Postgres write, new role, source-use approval, physical REST reservation or paid GO.
