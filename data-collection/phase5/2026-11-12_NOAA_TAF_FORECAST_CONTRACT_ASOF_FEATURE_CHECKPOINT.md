## Source-backed fields, not guessed weather

The [US NOAA Aviation Weather Center Data API](https://aviationweather.gov/data/api/) documents worldwide terminal TAF as JSON on `GET /api/data/taf`, plus 100 requests/minute rate limit, 400-result maximum and preferred bounded requests. Its documented JSON structure includes `icaoId`, TAF `issueTime`, `validTimeFrom/validTimeTo` in epoch seconds, and `fcsts[].timeFrom/timeTo`, change group, `visib` (statute miles) and `clouds[]` with `cover`/`base` (feet). We use the actual **pre-issue** source and validity intervals; **TAF is a forecast, not the observed weather outcome**.

The new [pure forecast decoder](../../server/lib/disruption/phase5AmendmentEExistingNoaaTafReceipt_v39.ts) accepts previously fetched/stored exact JSON bytes and separately reviewed response SHA, only origin/destination **ICAO** airport identities, original frozen native departure T, and distinct actual source-fetch, durable-artifact-read and prediction-issue timestamps. It emits `origin_taf_flight_category` and `destination_taf_flight_category` when and only when:

- Actual forecast `issueTime` was not later than our fetch and prediction issue; **GitHub artifact read** existed before prediction issue; forecast valid period covers exact native T.
- A single most recently issued TAF for that airport exists; a single `fcsts` period covers native T, with `fcstChange=null` or `FM` (prevailing). If overlapping `TEMPO`, `PROB`, `BECMG`, duplicate issued TAF, ambiguous periods, wrong airport, missing ceiling evidence, missing visibility, or unsupported format is encountered, record an explicit **missing** candidate rather than inventing a flight category.
- Derive standard categorical `LIFR/IFR/MVFR/VFR` from **visible reported prevailing forecast ceiling (BKN/OVC/VV in feet)** and **numeric visibility in statute miles**; `6+` is a lower bound exceeding 6 miles and is used only as a safe VFR visibility constraint. No claim that a TAF predicts *actual observed* weather or actual flight departure. If the source provides a forecast that cannot be reduced unambiguously to the two inputs, preserve NULL.
- Return only the two predeclared signed `NOAA_TAF` source observations with station/airport identity, source-record SHA, issue and actual durable availability, TAF segment validity. The same original [Stage14 as-of selection](../../server/lib/disruption/phase5AmendmentESignedSupplementalFeatures_v39.ts) checks station match, forecast validity at native T and no source after issue. The original [combined FIDS/METAR/historic bundle](../../server/lib/disruption/phase5AmendmentENoaaHistoricalReceiptCompiler_v39.ts) now accepts an **optional** `taf` source array, with exact ownership/duplicate/cross-flight checks, and still outputs the same ONE twelve-field signed-supplement contract.
