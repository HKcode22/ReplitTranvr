## New implementation in this branch

The new pure `server/lib/disruption/phase5ActualSourceNativeFlightCandidateAudit_v39.ts` **does not create a PRE packet**. It consumes exactly one already committed FIDS original read back through **existing Stage14 SOURCE SELECT** and up to 2,500 normalized `clean.flight_population` members through a new bounded projection. It requires immutable signed review pins (source query/manifest/day/horizon/airport, GH source run ID, rights/release/provider and early draw hashes) and real original timing: reservation <= provider retrieval <= raw persistence <= availability <= original binding <= PG observation. The original FIDS response hash and population query ID must match. It refuses changed/tampered custody and expired original. It classifies each independently observed member into **candidate requiring independent review** or a *per-flight censor reason* (missing/invalid native scheduled-T, unresolved codeshare/operating role, wrong origin/response, future-dated unavailable member, source too stale/expired, source arriving past own cutoff, too little prospective PRE lead, outside approved source window, duplicate ambiguous member ID). It never synthesizes T from a route, timezone, script test fixture, desired model target or previous conditional service key. No one flight's ordinary missingness invalidates valid others.

New manual-only `scripts/v39_phase5_actual_source_native_flight_candidate_readonly_owner_v39.ts` uses the existing verified dedicated PRE login and `REPEATABLE READ READ ONLY` PostgreSQL16 session. It verifies real SQL `current_user`, `transaction_read_only`, database and PG current time; queries the existing bound original via `P5_STAGE14_BOUND_SOURCE_SQL`, then all actual normalized members for its true post-COMMIT population ID. It refuses absent/duplicate original and >2,500 members **without silently truncating a busy hub**. It rolls back, destroys the restricted session, and emits ONLY aggregate candidate/censor counts and a fingerprint: **no provider raw payload, flight IDs, passwords or physical reservation data in GitHub Actions logs**.

New `.github/workflows/phase5-actual-source-native-flight-candidates-readonly-manual.yml` has a dedicated PR offline test-only job and main-only, manual `workflow_dispatch` reviewed-source observer (NOT a scheduled action). Explicitly requires owner review, original source GH run ID + hash pins, real source Contents rights, main code commit, and a true restricted PRE credential. Explicitly sets provider API key blank, runtime/SOURCE/REST DB URLs blank, `V39_PHASE6_PROCESS_ARMED=0`; **does not require or sign Phase5 scientific FREEZE/Phase6 paid GO** because this is a pre-freeze nonpaid *read-only review*.
