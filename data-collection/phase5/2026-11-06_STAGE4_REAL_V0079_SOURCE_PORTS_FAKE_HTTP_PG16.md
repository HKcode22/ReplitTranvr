This follows merged [Stage2 scoped source bridge #419](https://github.com/HKcode22/ReplitTranvr/pull/419) and merged [Stage3 staged V0079 SQL #420](https://github.com/HKcode22/ReplitTranvr/pull/420). ## What changes

1. **Explicit restricted PostgreSQL pool:** `persistFidsObservation(query,rows,beforeCommit,scopedPool)` now optionally accepts a caller-supplied `Pool.connect` implementation, keeping all historical call sites and lazy V39 runtime fallback unchanged. Stage4 ALWAYS supplies an explicit `scopedPool`, not the ordinary application pool. This is required for a dedicated future Github-only restricted source role.
2. **Real exact-query readback:** `phase5V0079ScopedDbPorts_v39.ts` requires an existing reviewed query in `clean.phase5_fids_allowed_query_v39`, checks calendar/config/frame SHA, provider contract, source request origin/timezone/local window, query key/day/slot/horizon, original four-airport draw SHA, release SHA, provider rights artifact SHA, actual GitHub run identity and exact API units before any physical reservation or GET.
3. **Durable physical attempt BEFORE GET:** the `reservePhysicalBeforeGet` port calls locked `clean.reserve_phase5_fids_physical_get_v39` as a separate PostgreSQL transaction and re-reads the immutable source-attempt row before allowing the source bridge to dispatch one HTTP GET. A timeout/unknown result does NOT retry; ambiguous billing is left unknown until independent provider reconciliation.
4. **Original + normalized row atomicity:** the `commitOriginalAndPopulation` port uses `persistFidsObservation` with the same scoped pool. Its `beforeCommit` hook validates that the signed query still matches and inserts `clean.phase5_fids_original_binding_v39` **inside the SAME transaction** as `clean.fids_query_response` and `clean.flight_population`. V0079's database trigger independently checks the reservation, source contract, decoded response body SHA, normalized row count, expiry and clocks. After COMMIT, the adapter independently re-reads the original metadata and returns a durable receipt; no PRE is fabricated.
5. **Real disposable PG16 proof:** the [isolated GitHub workflow](../../.github/workflows/phase5-stage4-v0079-real-source-ports-pg16.yml) boots actual B0062 plus staged V0079 into a disposable PostgreSQL16 service. It uses **fake local HTTP** only (zero live provider calls); tests wrong query/refusal, one irreversible reservation/GET, atomic raw original and normalized rows, and duplicate run refusal.

## What is not proven, not released and must remain HOLD

- This code is *not a timer*. There is no GitHub Actions workflow that activates a real FIDS query, no installed V0079 production roles/installer or source rights; `createP5V0079ScopedDbPorts` is a factory, never invoked by the published app or a scheduled job.
- The test uses an intentionally synthetic future service window with an earlier prospective source GET. It is **not evidence of native provider selected T**, actual-only wheels-off, full representative 4-airport frame, exact true T24/T6/T90 cutoff or full 31-day budget.
- An original's `available_at` and binding timestamp do not independently prove that PostgreSQL **COMMITTED** before every flight-level cutoff. The later authentic PRE owner must use a trusted source readback and DB clock; if cutoff missed, persist a missing/late status and do not backfill.
- Provider use rights, retention policy and actual API unit pricing need account-specific verification before any paid call; AeroDataBox's Nov7 terms update is not resolved by a signed SHA alone. A retention-expiry metadata row is not an automatic lawful deletion/TTL enforcement job.
- Live receiver currently reported an older published SHA in past public tests. Verify the deployed exact revision and raw-before-2xx receiver, webhook/P0 and independent STOP before any paid delivery experiment. A single success is not a reliability sample.
- Source concurrency/STOP, signed single-day early-adaptive policy, full freeze calendar + source intervals/overlap, GitHub source owner T24/T6/T90 workflows, V0076/V0077-derived PRE and POST/recovery, missingness/selection-bias QA and separate Phase6 GO all remain to implement and verify in [issue #416](https://github.com/HKcode22/ReplitTranvr/issues/416).
