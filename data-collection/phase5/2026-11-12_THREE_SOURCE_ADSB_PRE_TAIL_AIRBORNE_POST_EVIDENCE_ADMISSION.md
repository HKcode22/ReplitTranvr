## Straight answer to the owner

**ADSB.lol was present in this repo before this request**: a finite WSSS public source research probe, parser, short-sequence continuity model, Phase4 ADB+ADSB paired-source AIRBORNE admission, and November 9 ADSB physical-departure error/ODbL report. It is **not yet independently verified as a persistent source-bound production PRE incoming-tail join or POST continuous independent label collector**. The existing Phase4 dual-source gate intentionally rejects PRE and POST positions, admitting only the independently linked AIRBORNE candidate. It is inappropriate to represent that as already installed for all three phases.

This PR adds the *two missing nonpaid evidence contracts*, while reusing the Phase4 AIRBORNE gate unchanged:

1. [PRE: previously observed incoming aircraft position](../../server/lib/disruption/phase5AdsbLolCrossPhaseRotationEvidence_v39.ts) — before an original T−24h/T−6h/T−90m **issued-at** time, the ADB departing and incoming records must be **two distinct independently reviewed physical operating legs**, matching real original hash/assigned tail and ICAO24 aircraft, the inbound leg's destination must equal outbound origin, no aircraft swap/codeshare conflict, and both tail assignment times must have been available to our system before that PRE issuance. A bound, recently **received** (<15 minute candidate age) ADSB.lol aircraft position can then be marked as conditional incoming-aircraft position context. It cannot prove arrival at a gate, completed turnaround, a known next airplane assignment or an actual delay. A T24 previous flight often has no assigned aircraft yet; record NULL instead of inventing a chain.
2. [POST: last reported ground + first reported airborne sample](../../server/lib/disruption/phase5AdsbLolCrossPhaseRotationEvidence_v39.ts) — after independently reviewing the same physical ADB operated leg, one real transponder, departure airport track geometry, origin/receipt clocks, ODbL and source use, a chronological ground→airborne transition within a finite 20-minute gap can be stored **later** as a possible takeoff-time interval. It is not certified actual wheels-off or gate-out, even if the interval is narrow; the true transition could occur outside the interval because ADSB ground flags, MLAT, receiver gaps and operating/flight assignment can be wrong. Do not use it as the first-cycle primary actual gate-out label. It can be a separately tiered **proxy** when empirically calibrated to same-flight, same-milestone actual reference (for eligible US flights, some BTS actual wheels-off AFTER publication may help).
3. **AIRBORNE ETA** retains the existing [Phase4 AIRBORNE position gate](../../server/lib/disruption/phase4Gate5DualSourceAdsbAdmission_v39.ts), which checks as-of timestamp, independent source/physical identity, conflicts and rights. This does not itself generate a production ETA or a paid/persistent ADSB feed. Postdeparture forecast issuance must use only observations available before its *own* airborne issue, rather than later completed-flight trajectories.

The new regression tests enforce correct same-tail matching, receipt-before-PRE, future aircraft swaps, stale positions, independent per-horizon T and time cutoffs, 24h tail assignment availability, missing gate-in not becoming planned turnaround, live rights, correct POST ground→air ordering/airport geometry, contradictory identities, and retention of the legacy AIRBORNE gate. Output is a **reason/status plus bounded time/ground-state evidence**, not aircraft IDs, callsigns or raw lat/lon. No source query, new database row, original PRE update, automatic FeatureStore insertion, billed credit, or scientific claim is emitted. It uses the existing Phase3 WSSS normalized source shape and does not create a duplicate collector.

## Important distinction in the tail chain

Example: current flight WSSS→YSSY is scheduled 14:00; ADB independently confirms its physical incoming aircraft is flying OMAA→WSSS with the same actual transponder/tail. If the incoming ADSB.lol position was **received at 07:58** and the T−6h PRE issues at **07:59**, it may be a legitimate *inbound aircraft still airborne* risk signal. But it does NOT tell us the actual WSSS gate-in. The existing [true gate-in planned-turnaround feature](../../server/lib/disruption/phase5AmendmentETailChainAsOfCandidate_v39.ts) must remain NULL until a real inbound actual gate-in is known **by issue time**. BTS published weeks later cannot fill that gap retroactively. A third current flight may inherit only evidence available at that third flight's own forecast.

A matching **registration or ADS-B callsign alone** does not prove the two legs connect: flight reassignment, codeshares, transponder changes, incomplete adsb.lol coverage, receiver gaps and airline tail swapping require explicit missingness/ambiguity. A coded 'GROUND' sample is **not** an arrived-at-gate milestone.

A later position is useful only as POST/sensitivity evidence.
- [adsb.lol request key policy](https://www.adsb.lol/request) says ODbL compliance explanation is needed, free API access is best effort, production/commercial guarantees are not included. Review ODbL attribution/share-alike implications for any derivative database before combining with restricted AeroDataBox Contents; keep separate source layers and source-specific training right decisions.
- [BTS 2026 directive](https://www.bts.gov/explore-topics-and-geography/modes/aviation/number-40-technical-directive-reporting-time) distinguishes *actual gate departure*, *actual wheels-off*, *actual gate arrival*, and aircraft tail. The already downloaded and independently verified [real August 2026 BTS dataset](2026-11-12_REAL_BTS_2026_AUGUST_608389_VERIFIED_NORMALIZED_ARTIFACT_READBACK.md) holds **608,389** U.S. reporting-carrier records in an isolated 30-day GitHub artifact; it must **not** be mixed into the live ADB FIDS source population, or used as if its later outcome existed at a historical PRE cutoff.
