## The questions that must be answered first — READ the plain-language sections, not raw SQL

The [ADR C+D — “READ THIS FIRST” and §11 code-reading map](2026-11-10_ADR_PHASE6_AUTONOMOUS_C_PLUS_D_HYBRID_DESIGN.md) and [independent audit — “OWNER'S READING GUIDE” and §10 code map](2026-11-10_INDEPENDENT_PHASE6_PARALLEL_AUTOMATION_DESIGN_AND_BUDGET_AUDIT.md) have been **edited in place** to explain:

1. A **task** = one eligible flight × one PRE horizon, not a GET or a new airplane; 100 tasks are *synthetic scenario* not a claimed real cohort. Four worker **lanes** = at most four independent Stage14 flight snapshots processing at once. 1/2/4/8/16 are only configurations to benchmark. Five seconds/transaction was hypothetical. **96-packet shard** = one page of 96 immutable one-flight/horizon instructions, not a hard 96-flight study cap.
2. One flight originally scheduled 18:00 UTC has prediction cutoffs T−24h (previous day 18:00), T−6h (same day 12:00), T−90m (same day 16:30). These are **relative to every individual flight**, not three arbitrary daily collection times. The current Stage14 writes within the last ~3min before its OWN cutoff, no after-cutoff **backfill**.
3. A transaction = short all-or-nothing SQL unit; waiting until a flight becomes due should NOT hold a database connection or transaction lane. A queue = durable to-do table (not duplicate raw flight storage); a read-only reconciler = distinct checker for an UNKNOWN_COMMIT. **Atomic claim** = one owner acquired in a single transaction; `SKIP LOCKED` allows other workers to claim other waiting tasks; lease/fence ensures an expired owner cannot race a new owner. Do not replace one SQL writer with N copies.
4. 31 parent days = 26×4h (104h) + 3×2+gap+2h (12h active) + 2×up-to-6h (12h) = **128 maximum active segment hours**, arranged as **34 active blocks**. Four airport sample slots × 34 segments × three PRE horizon planning classes = **408 logical groups**, NOT 408 FIDS GETs or physical flights. The 21 ordinary future adaptive selections are unknown until legitimately chosen **>24h45m and ≤72h** before parent window.
5. More frequent FIDS **refresh** costs more: for a single continuously active four-hour source group, one/hour = 4 GET, one/30min = 8, one/15min = 16, one/10min = 24, one/5min = 48. Four airports × three hypothetical distinct horizon groups × 4 GET = **48 GET / 96 Tier2 API units** in that simplified four-hour example; actual horizons/UTC times/partitions may differ. One paid GET may return many flight records.

7. **Seven REST categories** are V0082/V0083 cost buckets (FIDS BASE, FIDS SPLIT, FIDS RETRY, VALIDATION, OUTCOME/POST, HISTORY BOOTSTRAP, DIAGNOSTIC), **not seven data providers**. Later “bind original” records a genuine saved provider response and its actual available-at clock. “Normalize” converts nested SOURCE into rows with codeshare and missingness. **TTL** is permitted retention duration.
8. **Flight Alert webhook**: based on approved airport/flight scope, independently authorize provider CREATE, receive asynchronous provider PUSH notifications in the *Replit published raw-first webhook*, verify owned subscription and credentials, persist originals, reconcile SEND-credit charges (not merely deliveries), and STOP/DELETE only owned IDs. PK/lease/sidecar/semantics are explained before use. Hash is byte equality, **not proof of source rights**. Because GitHub repo is public, private flight content/packet lineage must not be automatically posted publicly before a lawful-use review.
10. **Weather:** free NOAA METAR is an observed airport-station condition. Existing cutoff-safe selector supports one airport's METAR (within configured distance/age), not the **whole route**, and Stage14 currently constructs PRE with `features:[]`. To model origin, destination or en-route conditions, independently match genuine flight origin/destination/ETA/route to valid early-issued TAF/SIGMET/forecast grid; missing weather remains NULL, not substituted from unrelated airports.
