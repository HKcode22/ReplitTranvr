# November 15 — rolling controller failure custody and experiment-length evidence

## Why this matters
The bounded rolling controller previously uploaded its terminal receipt only on success. It deliberately stops on an uncertain worker POST, successor POST, missing history, or failed reconciliation; failure evidence could therefore exist only in logs. A later fresh root must never interpret missing terminal evidence as no prior work. A 7-day successful receipt lifetime was also shorter than the proposed 31-day collection.

## Candidate implementation
Reuse the existing rolling controller, workflow, ACK ledger and fixed routes. Before any network request initialize a private runner-local file under RUNNER_TEMP with exclusive creation and exact scope (main, run ID, parent, hop, original epoch and deadline). Project only finite control-plane events: worker attempt before POST, exact worker ID acknowledgment, independently reconciled terminal ID, successor attempt before POST, exact successor ID acknowledgment. Flush each record synchronously before returning to the caller. Never persist raw provider data, request bodies, error strings, tokens, database credentials, or flight identities. At most 300 records / 64 KiB. Run-time write failure stops rather than authorizing a replay. On ordinary workflow failure attempt to upload a sanitized failure-only journal for 90 days. Successful terminal receipt retention also becomes 90 days; successful parent still has its original single terminal artifact, same required job and step names. Existing session/deadline/ACK/STOP/rights/budget gates unchanged.

The journal does NOT grant permission to dispatch. A missing ACK after an attempt is unknown; a run ID is not execution/paid evidence; even a terminal worker marker is not a flight receipt. A destroyed or forcibly cancelled runner may lose the local file before upload. This is best-effort evidence preservation, not globally durable pre-POST intent or month-long autonomous restart. No failed predecessor is accepted by the current successor. Do not retry uncertain POSTs or start a new epoch based only on this journal. Actual GitHub artifact settings may cap retention; verify actual artifact metadata before production reliance.

Integrated actual-shaped mock tests exercise a failed worker POST and accepted successor, verifying on-disk evidence before the mocked POST and before terminal receipt.
