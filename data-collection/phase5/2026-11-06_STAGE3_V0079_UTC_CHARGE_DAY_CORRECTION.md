# Phase5 critical budget correction — physical FIDS GET charged on UTC **dispatch** date

**Nov6 2026 PST.** Staged V0079 had a serious accounting mismatch: each actual paid GET charged monthly units and a day ledger keyed by the flight's **service run day**. That is wrong for e.g. T−24h source requests issued the preceding UTC day, and can allow the real UTC 1900/day cap to be exceeded when sources for two service dates are queried during the same UTC day. **No V0079 production installation or paid calls occurred; fix the staged schema before any release.**

## Corrected V0079 protocol

1. Preserve `phase5_fids_day_budget_v39` (scientific service run-day attribution and conservative additional per-run-day reservation), but **add** `phase5_fids_utc_charge_budget_v39` with PRIMARY KEY (manifest, actual UTC charge date), signed cap ≤1900, other-provider-category reserve and actual FIDS physical units. Include **Day0** (the UTC day before service day1) whenever T−24h starts ahead of service.
2. The allowed query preregisters `planned_charge_utc_date`, bound to `planned_dispatch_utc AT TIME ZONE 'UTC'`. Every physical reservation uses actual `clock_timestamp()` and **must match the signed planned UTC charge date**; an overnight late dispatch is refused rather than silently billed in the wrong bucket.
3. `reserve_phase5_fids_physical_get_v39` transaction locks cycle, query, service day and **actual UTC charge day**. It refuses an absent actual-day row, actual-day overspend, day mismatch, or dispatch during the UTC 23:50–00:00 buffer. It reserves the exact **two physical units once in ALL THREE ledgers**: project cycle, scientific service-day and actual UTC charge-day. Missing/failed/unknown provider responses are never refunded.
4. The immutable physical attempt row now stores `charged_utc_date` with a direct foreign key to the actual daily charge table, allowing independent billing-day audit and reconciliation. Before a GET, signed query/current rights, early four-airport draw and frozen source/T clock still must be valid.
5. **Offline tests** must demonstrate a source query for a service day tomorrow is charged today; missing Day0 row and exhausted today cap both fail *without a physical GET*. Stage4 fake HTTP+PG and Stage3 direct SQL tests must pass against the actual revised B0062+V0079 schema. No production migration, no SQL grant and no provider call in this PR.

## Still unresolved before live

- The separate **offline planning grid** `phase5FidsFreezeGridAdmission_v39.ts` presently assumes each query's `budgetDayUtc` is the service day; it is not correct for physical UTC charge-day budgets. The full 31-day release manifest and per-category other-source reservations must be updated to cover all actual UTC dispatch dates, even outside the 31 service-day interval; a green old grid arithmetic result is **NOT** billing-day proof.
- Other source categories must reserve their **same actual provider charge UTC days**, not just the study service-day. The actual provider billing/time zone/REST contract remains to be independently established. A physical reservation before GET is a conservative project spend commitment, **not the source's external billing receipt**; reconcile independently.
- Required Stage5 real GH owner prearm, source rights/licensed retention and current plan API unit pricing, exact published receiver SHA, lawful expiry/deletion and final Phase5 FREEZE are all OPEN. A real T−24h FIDS original does not certify each individual flight-level PRE or physical operating leg. No paid experiment or live DB installation from this change.
