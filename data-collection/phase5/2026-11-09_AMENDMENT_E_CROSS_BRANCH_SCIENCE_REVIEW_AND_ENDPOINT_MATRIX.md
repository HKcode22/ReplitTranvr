## 4. Concrete scientific traps the implemented scorecard must reject

1. **One source query ≠ one flight.** An airport-slot-day (31×4=124) is not a flight or GET count. Nov6 36 PRE comparisons correspond to 12 conditional service keys, not 36 independent physical flights, and no ≥15 schedule-revision positives in that cohort. Cannot estimate reliable severe-delay discrimination from it.
2. **Actual versus estimated/conditional identity.** The physical label endpoint must have both actual-only and native-leg evidence. Retaining a `runwayTime` from a provisional flight response does not provide that proof. A conditional service key may be valid for a *schedule-revision* estimand but remains a different stratum.
3. **Endpoint-specific UNKNOWN/CENSORED.** Status missing/expired/callback silence ≠ true negative. Count labels observed+unknown+censored+pending against the **prospectively eligible** specific population, and separately count *joint* valid as-of PRE **and** valid label (not two marginal counts).
4. **Leakage/selection.** One future flight identity, all aliases and horizons must occupy one of 20 TRAIN / 5 VALIDATION / 6 locked TEST parent-day partitions; reobservations and the same crossover airport set require group-aware handling. Do not read TEST outcomes for Phase5/Phase6 tuning. A 6-batch-day TEST has few independent day clusters: even thousands of correlated flights cannot guarantee a stable bootstrap significance claim.
5. **Do not transplant physical MAE counters to proposed D binary Brier.** The existing `auditP5RouteAndModelDataSupport()` counts physical `observedDelayOver15/60/120`. It remains valid for its current declared physical-label metadata. Reusing those counters to score provider schedule revisions without a separate endpoint category would invent mislabeled severe physical events.
6. **Purpose-limited minimal collection.** Existing allowed FIDS source originals can inform multiple labels per the same authorized observation, but only after source-class purpose and expiry approval. Optional NOAA/BTS/ADSB data are separate licensable provenance and never required to decide whether a valid PRE exists. Seven physical UTC REST budget classes and Alert STOP remain controlling; do not add unlimited data polling to chase rare outcomes.
