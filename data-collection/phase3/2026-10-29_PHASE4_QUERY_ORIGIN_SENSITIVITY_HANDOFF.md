## Change
`phase4Gate5QueryOriginSensitivity_v39.ts` introduces an **explicitly provisional sensitivity tier** with a single bounded, read-only, parameterized PostgreSQL `WITH ... SELECT` aggregate over already-retained unexpired FIDS original JSON from the same max 12 selected receipts. It counts provider operator-tagged departure observations, those relying only on query-origin context, explicit origin agreements/conflicts, missing number/destination/schedule, positive/negative/unknown cargo-private-charter scope flags, and complete source syntactic fingerprints versus distinct exact repeated fingerprints. A fingerprint uses only requested airport, flight number, destination ICAO, and scheduled UTC; **not a physical-flight identifier**. Two FIDS versions may describe a retimed single leg despite different fingerprints. Marketing records are excluded from the candidate tier.

`phase4Gate5SourceInventory_v39.ts` now includes this candidate report as an optional source-evidence dimension, automatically within the existing protected [main-only GitHub metadata audit workflow](https://github.com/HKcode22/ReplitTranvr/blob/main/.github/workflows/phase4-gate5-wsss-original-source-inventory-readonly.yml) after checked merge. No raw flight identities, hashes, schedules or location data appear in output. No SQL write, provider key or new provider GETs; existing REPEATABLE READ READ ONLY and ROLLBACK. Negative tests guard impossible counts, expired source exclusion, wrong scope, repeated fingerprints and source leakage.

## Non-negotiable science boundaries
Even a positive candidate never modifies `flight_population.canonical_flight_instance_id`, `scope_classification`, first provider-native T or schedule versions. Original records are immutable. Query-origin is documented evidence but cannot by itself certify airline-operated **physical** flight uniqueness. Provider `IsOperator` is a per-record status, not a unique leg. A commercial-passenger distinction needs confirmed cargo/private/charter semantics; UNKNOWN stays UNKNOWN. No T−24h/T−6h/T−90m retrospective credit, certified actual runway delays or POST trajectory links. Strict Gate5 remains HOLD; Phase5 final FREEZE and paid Phase6 remain NO-GO. The actual sensitivity output must be inspected after the postmerge GitHub audit; synthetic tests are not live findings.
