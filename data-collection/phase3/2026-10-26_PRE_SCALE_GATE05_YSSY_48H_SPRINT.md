### The TWO scientific blockers, not a "zero-error" demand

1. **Predictor decision T / source as-of:** `T_i` is the frozen FIRST independently verified provider-native scheduled milestone for flight `i`, not arbitrary final `scheduledTime` or timestamp of a postflight GET. PRE nominal decisions are exactly `C_{i,h}=T_i-h` for `h=24h,6h,90m`. Valid population evidence and each feature must have **durable** knowledge availability `available_at ≤ C`. The actual API fetch/retry and downstream build may finish before or after the nominal `C` (subject to the separately frozen acquisition guard), but a late response can NEVER be pretended available at an earlier decision. **Do not confuse exact nominal cutoffs with needing HTTP responses at an exact millisecond.** The current `materializePreSnapshotsForCutoff` interface takes one *batch-wide* `cutoffUtc`; it now checks exact `T-C=h`, but a batch-wide instant cannot represent arbitrary individual T timestamps across the service interval. This needs an explicit per-flight scheduler/materialization review and tests, not arbitrary ±3-minute horizon drift or silently dropped otherwise eligible flights. Until resolved, that specific Phase4 snapshot materializer remains **not fully flight-wise science certified**. The `verifiedProviderNativeSchedule:true` + SHA config is an **operator assertion**, not an authenticated source-semantic certificate. Future actual provider-milestone selection requires independent reviewed evidence.
2. **Original runway-delay label (distinct target):** `Y_i=[actual_wheels_off_i]-[scheduled_wheels_off_i]` in minutes, **NOT** automatically `departure.runwayTime - departure.scheduledTime`. The FAA [ASPM individual-flight definitions](https://www.aspm.faa.gov/aspmhelp/index/ASPM__Individual_Flights__Definitions_of_Variables.html) distinguish schedule gate vs runway and define estimated *scheduled wheels-off* as scheduled gate-out + unimpeded taxi-out; [ASPM downloadable variables](https://www.aspm.faa.gov/aspmhelp/index/ASPM_Data_Download__Definitions_of_Variables.html) list independent `WHEELS_OFF` and `OAG_OFF` (for US-covered sources only, with per-record actual/estimated provenance). AeroDataBox FIDS `runwayTime` can be actual/estimated, and it was **missing in all 33 sampled objects per variant**; `scheduledTime` has unverified runway/gate meaning. Thus exact runway target `label_status=missing/not_observed`, NEVER zero minutes, and original full Gate0.5 scientific rubric remains **not proven**. Even an ADA populated runwayTime is not an actual event without field-level actuality evidence. A deliberately **renamed** proxy (e.g. independently verified actual off minus *scheduled gate-out*) is a different estimand with gate-to-runway taxi component bias, requiring prospective owner/research protocol choice and reporting—not silent relabeling.
