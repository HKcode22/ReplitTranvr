# Phase 4 Gate 5 — prospective FIDS source-request provenance contract
Date: 2026-10-29. Binding V3.9 Plan f.8 §§4.3,5,5.1–5.4,6.1,7.1,16–17 and Implementation Log §§1.9,2.22. Append-only implementation checkpoint. Do not retroactively change old source.

## Why this patch is necessary
[Protected WSSS original-source audit #40889629496](https://github.com/HKcode22/ReplitTranvr/actions/runs/40889629496) proved 2 retained reconstructed FIDS query receipts, 31 normalized source observations and 9 provider-marked IsOperator records; no independently confirmed physical operating-leg population and zero matching PRE snapshots. The existing `fetchFidsPopulation` had input `withCancelled`, `withCodeshared`, `withCargo`, `withPrivate`, yet forwarded only `direction`, `withLeg` and `category` to the gateway. The lower-level gateway had a different hard-coded filter set: cancelled=true, codeshared=true, cargo=false, private=false. Thus the actual request was not bound to the caller's declared options; the persistent reconstructed JSON lacked explicit request filter provenance. The previously recorded WSSS paid one-time operator used custom fetch with explicit URL parameters but old historical receipts do NOT gain transport-level proof from this code fix.

## Corrective code for new observations
- `aerodataboxLimiter_v3.ts` accepts explicit Boolean frame filters and encodes them as named FIDS query parameters, preserving the old direct-call defaults when absent.
- `fidsCensus_v3.ts` now validates and freezes an `application-intent` request frame containing departure/arrival direction, airport and local range, source contract versions, withLeg=true, withCancelled, withCodeshared, withCargo, withPrivate and withLocation=false. The same effective values are passed to the gateway and stored within the append-only reconstructed `raw_payload` under `fidsRequestContract`. Existing `response_hash` now binds this intent for NEW queries.
- The source marker `payloadRepresentation=RECONSTRUCTED_RESPONSE_JSON_NOT_VERBATIM_HTTP_BYTES` and `originalHttpBytesPreserved=false` is deliberate: the old gateway parses FIDS JSON and constructs a new wrapper. This is not an immutable byte-for-byte original HTTP payload receipt; separate original source-byte custody remains an unfinished scientific gate, and a normal JSON rehash must not claim it.
- Explicitly refuse non-Boolean filters, invalid direction, airport code, or malformed local time range before issuing a billable FIDS GET. Honor correct local time strings; no substitution of UTC without airport timezone verification.
- Update two old synthetic tests that used invalid local time strings; add source-intent hash binding, actual gateway URL mocked capture, direct legacy default, and pre-provider rejection coverage. These tests make **zero** live provider requests. Runtime provider quota/callback/physical identity remains separately gated.
- The source contract is request-**intent**, NOT an independently verified provider server-side filter receipt. AeroDataBox official OpenAPI defines withCargo/withPrivate as filters subject to coverage; even captured false flags cannot automatically promote unknown charter/passenger scope or establish unique operated physical legs. Do NOT rewrite any historical confirmed-core/canonical IDs; current Gate5 remains scientific HOLD.
