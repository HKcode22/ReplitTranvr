## No-cost candidate sources and legal constraints

1. **adsb.lol free live API**: documented `GET https://api.adsb.lol/v2/point/{lat}/{lon}/{radius_nm}` with geographic radius up to 250 nautical miles; live aircraft fields typically include `hex`, `flight`, `lat`, `lon`, `now` milliseconds and `seen_pos` seconds. Public docs https://api.adsb.lol/docs and https://www.adsb.lol/docs/open-data/api/ . License **ODbL 1.0**, with attribution and share-alike rules for adapted databases used publicly: https://opendatacommons.org/licenses/odbl/summary/ . The official API docs explicitly request **contact before production use**; no presumed unmetered or uninterrupted access. Obtain operator coordination and license review before live GitHub scheduled collection or persistent merged AeroDataBox/ADS-B derived database. No recurring request yet. There is no price in the public API usage, but external bandwidth, storage, and reliability still matter.
2. **adsb.lol open daily historical traces**: https://www.adsb.lol/docs/open-data/historical and https://github.com/adsblol/globe_history_2026/ . Readsb traces/heatmaps are archived under ODbL as day/replica tar fragments. Open historical post-hoc sources can *measure* WSSS ADS-B coverage and source join feasibility for the UTC 2026-10-29 experiment, but **cannot certify any PRE feature as available at T−24h/T−6h/T−90m** if observed only through a later downloaded archive. Daily whole-sky prod files are **multiple GiB compressed (~3.6 GiB on Oct 26)**, so NO automatic full download into Replit or GitHub CI; avoid storage/bandwidth/compute bills. Historical flights are reconstructed from ADS-B trajectories and **estimated** departure/arrival airport/times, not independent truth of actual takeoff. `/states/all` has narrow recent-time access; anonymous public API daily 400 credit budget / authenticated standard 4,000, and its public Terms https://opensky-network.org/about/terms-of-use require a **written agreement for REST API operational automation**, including nonprofit automated workflows. ## Code delivered, deliberately non-production

`server/lib/disruption/gate05ZeroCostAdsbEvidence_v39.ts` implements a **pure, offline-only**, provider-literal `adsb.lol` v2 point response parser with WSSS reference coordinate from Singapore CAAS published ARP (01°21′33.16″N, 103°59′21.57″E). Requires raw response `now` in milliseconds; recorded real response reception clock and ±120s snapshot clock skew; max 30s `seen_pos` source freshness (parameterized, bounded), bounded search radius, lat/lon; separately preserves approximate ADS-B observation time `now - seen_pos` vs *available_at* (actual response arrived). Anonymous aggregate reporting cannot leak aircraft hex/callsigns/coordinates. All positions remain `UNLINKED_AIRCRAFT_CANDIDATE` with `runwayEventActualVerified=false`; as-of cutoff eligibility always uses `receivedAtUtc`, **not** reconstructed source event time. The module does **zero provider HTTP calls, SQL writes, Replit object mutations, subscriptions or secrets management**. Includes offline tests; does not replace AeroDataBox's code path or ship a new live source collector.

## Two scientific tracks: solve different problems, don't conflate them

- **TRAJECTORY/POST source**: Need *verified* timestamped ADS-B points per airport and enough independently linked operated legs; a free API response is not yet proof of reliable WSSS coverage. Require a no-cost source permission/terms and measured bounded POST coverage pilot before long-run admission. Different ADS-B icao24 hex and airline callsign may refer to one aircraft or be missing/changed; match only with candidate confidence using AeroDataBox operating carrier/flight, origin/destination, service day and temporal continuity; ambiguous matches are **quarantined**. Preserve source-native aircraft ID privately under retention restrictions and an independently reviewed licensing plan, not in public GitHub logs.
- **LABEL/PRIMARY TARGET**: The official AeroDataBox provider `departure.scheduledTime` is generic scheduled departure, `departure.runwayTime` can be actual **OR estimated**. ADS-B can approximate state change/takeoff interval from an aircraft track but **does not independently prove a precise wheels-off timestamp or that scheduled departure equals scheduled runway wheels-off**. Exact original `actual_wheels_off - scheduled_wheels_off` remains a P0 identifiability blocker. To proceed, either establish authoritative schedule + verified actual runway source, or **formally amend and version** the scientific primary target (e.g. observed airborne-by-T classification, NOT exact delay) with independent evaluator acceptance BEFORE collection; do not silently redefine existing f.8. Keep missing labels NULL and avoid using eventual outcomes as past PRE information.
- **DURABILITY**: Pilot's physical flight/item runtime was PostgreSQL UNLOGGED and became 0 after restart, despite original bytes surviving in App Storage. For a long run, decide a durable lawful logged/append-only derived source/index before paid exposure; unit test actual PG postmaster restart and recover exact sample identity+trajectory+as-of from retained originals with no lost membership. No 168h original-retention extension without authorization; preserve only lawful required derived evidence. The pilot's DB owner remains `ACTIVE` despite provider verified inactive; close via a distinct reviewed, authenticated one-shot DB-only exact owner STOPPED transition with post-commit readback, no provider mutation.
- **NO COST ESCALATION**: No new paid provider, no rest-credit probes, no spending authorization inherited from Gate05, no automatic multi-GiB archive downloads, no Cloudflare, no Replit AI Agent. No Phase4/6 paid admissions until scientific/provenance/coverage and terms pass. No need to delay offline work or inspect YSSY.
