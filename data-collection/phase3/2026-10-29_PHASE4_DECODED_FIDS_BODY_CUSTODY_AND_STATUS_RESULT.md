## Prospective source-body implementation (this PR)

The existing bounded `fetchFidsAirport` gateway now reads a successful FIDS response with incrementally bounded `Response.body.getReader()` streaming (not an unbounded `arrayBuffer()` allocation), captures the exact bytes delivered by Node fetch, computes SHA-256 over the actual Buffer, enforces a 4 MiB decoded-body cap and passes evidence to `fetchFidsPopulation`. The latter verifies the byte count, canonical base64, SHA and parsed departures/arrivals against the gateway result **before** persisting, then binds an embedded base64 payload, SHA and representation marker into the existing atomic `clean.fids_query_response.raw_payload` and its current `response_hash`. This reuses the current append-only FIDS/raw availability transaction, not a new collector or migration. The existing retention/expiry mechanism must be applied to all retained source content; no request is performed by this code-only PR.

**Precise limitation:** Node fetch may decompress content transparently, so these are *fetch-decoded provider response-body bytes*, **NOT** original compressed HTTP wire/transport bytes or an independently signed server-side receipt. The existing `fidsRequestContract` is application intent, not network attestation. The wrapper remains `RECONSTRUCTED_RESPONSE_JSON_NOT_VERBATIM_HTTP_BYTES`; the decoded-body flag and hash are separate. Tests with legacy/mock results lacking byte evidence retain `originalDecodedEntityBodyPreserved=false`; historical 31 WSSS records and the one paid Flight Status probe are untouched. Source-body custody is only established **prospectively for future FIDS calls executed with the repaired gateway**, not retrospectively.
