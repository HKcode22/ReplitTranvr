## Root-cause decision tree; only evidence-backed branches

1. **Provider never reached published host:** provider delivery logs show DNS/TLS/network timeout, callback URL/hostname incorrect, or no HTTP result. Replit application-level logs may be empty; published App Analytics route/status distribution may help but may not include all edge failures.
2. **Provider reached host, HTTP != 2xx:** obtain redacted status 404/400/415/422/413/503/5xx or timeout and approximate time. `415` would focus on content-type; `422` on schema/claimed subscription/subject; `503` on V0071 database or role (safe `GATE4_PREBIND_SQL_STAGE`/SQLSTATE if logged). Do not assert a status from source alone.
3. **Provider reports 2xx but V0071 scoped original missing:** reconcile exact destination/host, actual published release identity, storage role, V0071 scope, and any upstream proxy issue using narrowly redacted provider request ID and published app event metadata; this is a higher-severity custody discrepancy.
4. **Provider reports no SEND/charges unrelated:** provider must explain actual debit and billing period; account balance by itself is not per-notification proof.
5. **Historical logs unavailable:** record this explicitly; require newly instrumented receiver to pass one **separately authorized**, scoped, small live positive original test. Never repeat spent NEXT1/NEXT2 or invent a provider callback for completion.
