## Purpose and trigger

Previously the Phase4 original decoded FIDS readback code was fully unit-tested, but **there was no real retained-production-DB readback evidence** from the newly committed algorithm. The repository already has the protected GitHub-only `phase4-gate5-wsss-original-source-inventory-readonly.yml` reader workflow in environment `phase2g-paid`, with `GATE05_AUTOMATION_DATABASE_URL`. Reuse that restricted credential source rather than requiring fragile timed Replit commands or inventing new secrets.

This PR adds an automatic, **one-shot GitHub Actions main-push read-only** workflow `phase4-gate5-protected-fids-original-readback.yml` and operator `scripts/v39_gate5_decoded_fids_readback_actions.ts`. It triggers when the workflow or owner script arrives on main, checks exact main SHA, GitHub first run attempt and explicit read-only intent, authenticates using only the previously used existing protected DB URL (no AeroDataBox key), then opens one **REPEATABLE READ READ ONLY** transaction and two bounded source checks for WSSS and YSSY, from one read-as-of timestamp.

Each source read selects at most five recent unexpired `clean.fids_query_response` rows (four inspected plus lookahead), excludes records already marked `raw_expired_at_utc`, and independently applies `raw_persisted_at_utc >= read_as_of-24h` as a hard upper age guard in case retention expiry was delayed. The source-content age guard is an **additional safeguard, not evidence that the actual account plan grants retention or the backup/replica expiry job has already complied**. Body bytes never leave process memory or appear in logs. The runner emits only count/status summaries, with no flight IDs, request IDs, raw FIDS JSON, base64, provider API keys, DB URL, or payload hashes.

Returned counts distinguish (a) original fetch-decoded body byte/SHA and source-arrays integrity, (b) future JSONB-stable body+envelope integrity, (c) earlier body-only legacy rows, (d) no lawful retained source, and (e) rejected integrity. Zero records are **UNMEASURABLE**, not a zero coverage rate or Gate5 PASS. Any actual readback corruption fails the job. Authentication/permissions/schema/connection errors are redacted and fail closed. Underlying readback scope is capped; a green job is a successful audit execution, **not a complete source census**. No DB mutations, provider REST calls, Alert subscriptions, paid units, schedule, Cloudflare or Replit commands are triggered.
