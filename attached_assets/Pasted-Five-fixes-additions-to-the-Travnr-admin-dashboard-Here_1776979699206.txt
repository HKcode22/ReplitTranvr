## 2. Add manually booked flights to My Trips page

In `GET /api/trips`, currently it only returns payments where duffelOrderId is not null. Update it to also return payments where status = 'paid' AND duffelOrderId IS NULL but manualBookingDetails is not null.

For manual bookings, construct the trip object from manualBookingDetails instead of fetching from Duffel:

```typescript
{
  id: payment.id,
  bookingReference: payment.duffelBookingRef,
  duffelOrderId: null,
  amount: payment.amount,
  currency: payment.currency,
  status: payment.status,
  bookedAt: payment.createdAt,
  proposalId: payment.proposalId,
  isManual: true,
  order: {
    booking_reference: payment.duffelBookingRef,
    slices: manualBookingDetails.slices || [],
    passengers: manualBookingDetails.passengers || [],
    total_amount: payment.amount,
    total_currency: payment.currency,
  }
}
```

In `client/src/pages/trips.tsx`, make sure trip cards render identically for both manual and Duffel bookings. If a manual booking is missing fields Duffel normally provides, use sensible fallbacks — e.g. show manualBookingDetails.routeSummary if slices are empty.

## 3. Show manually confirmed bookings in admin Recent Bookings table

## 4. Fix the Duffel balance "Update" UI

In `client/src/pages/admin-dashboard.tsx`, fix the balance stat card so:
- The estimated balance amount displays normally in the card
- There is a small lucide Pencil icon (14px) next to the number, always visible
- Clicking the pencil replaces just the number with a small inline input (pre-filled with current value) + a green checkmark button to save + a grey X button to cancel
- On save it calls POST /api/admin/duffel-balance/update and refreshes the display
- On cancel it goes back to normal display
- Remove any separate "Update" button — the pencil icon is the only edit trigger
- Below the balance number show small grey text: "Est. · Last set {date}"
- Color the balance red if under $100, yellow if under $300, green if $300 or above

## 5. Email preview and test panel in admin dashboard

Add a new "Emails" tab to the admin dashboard tab bar (alongside Pending Manual, Bookings, Payments, Users, Calls).

In this tab show a card for each email type Travnr sends:
- Booking Confirmation (manual)
- Email Verification
- Password Reset
- Account Creation After Call
- Booking Failure Alert

Each card shows:
- Email name
- One-line description of when it triggers
- "Preview" button — opens a full-screen modal (90vw x 90vh) rendering the email HTML in an iframe with realistic sample data
- "Send Test" button — sends the actual email to the logged-in admin's email via SendGrid with sample data

Sample data to use everywhere:
- Passenger name: "Mahid Abdulkarim"
- Route: "STL → JFK"
- Departure: "May 15, 2026"
- Booking ref: "TRAVNR"
- Amount: "$342.00"
- Airline: "American Airlines"
- Recipient: the logged-in admin's actual email

Add a new endpoint `POST /api/admin/email/test` protected by isAdmin middleware. It takes `{ emailType: string, recipientEmail: string }` and sends the appropriate email using the existing SendGrid functions already in `server/routes.ts`. Refactor all email HTML generation into standalone reusable functions at the top of routes.ts so they can be called from both the normal flow and this test endpoint.

The preview modal should render HTML in an iframe so it displays exactly as it would in an email client. Make it closeable with an X button or clicking outside.
